# 传统 RAG vs Graph RAG 使用场景区别

## 一、核心机制差异（决定场景适配）

| 维度 | 传统 RAG | Graph RAG |
|------|---------|-----------|
| 检索依据 | 向量相似度（语义接近） | 知识图谱（实体+关系拓扑） |
| 检索单元 | 独立文本块（chunk） | 实体节点 + 关系边 |
| 跨文档能力 | 弱（块之间无关联） | 强（图遍历天然跨文档） |
| 推理深度 | 浅（top-k 拼接） | 深（多跳路径遍历） |
| 适合的查询粒度 | 局部、点状 | 全局、链状、网状 |

## 二、传统 RAG 适用场景

**查询特征：局部、事实性、答案集中在少数段落**

1. **单点知识查询**："X 的定义是什么""某不良代码 0x12 含义"
2. **独立文档检索**：SOP 作业指导书、设备操作手册、规格书查询
3. **答案局部化**：所需信息就在 1~2 个 chunk 里，不需要跨文档综合
4. **数据扁平、量大**：文档间无强关联，如 FAQ 库

> MES 典型：查某工单的 SOP、查某型号贴片机的参数说明、查某测试项的标准值。

## 三、Graph RAG 适用场景

**查询特征：全局、关系性、需要跨文档聚合或路径推理**

1. **全局总结性查询**："本月质量问题的主要主题有哪些""整个产线异常概览"（传统 RAG 只能返回相似段落，做不了主题归纳）
2. **多跳关系追溯**：物料 → 供应商 → 其他批次 → 产线（链式追溯，向量检索无法跨越关系）
3. **影响范围 / 根因分析**：A 工序异常 → 影响哪些工单 → 影响哪些客户（图遍历天然胜任）
4. **实体密集关联**：物料、批次、工单、设备、人员、供应商之间网状关联
5. **答案分散在多文档**：需要把散落的信息按关系拼起来

> MES 典型：质量追溯（某物料来源全链路）、不良根因分析（跨工序关联）、供应商影响面排查、批次召回范围圈定。

## 四、MES 生产数据为什么必须用 Graph RAG？传统 RAG 的弊端

### 4.1 MES 生产数据天生是"图"，不是"文档"

MES 生产数据的核心特征是**实体密集关联、链路化、时序化**：

- 工单 → 工序 → 设备/人员/物料 → 批次 → 供应商 → 客户，构成**网状拓扑**；
- 每一次追溯、每一次根因分析、每一轮召回，本质都是在**这张图上做路径遍历**；
- 数据的价值不在单个文本块，而在**实体之间的关系**（谁用了谁的料、谁影响了谁）。

这类数据**天然贴合知识图谱结构**，而非扁平文档库。传统 RAG 以"语义相似"检索"关系型数据"，是南辕北辙。

### 4.2 传统 RAG 在 MES 生产数据上的具体弊端

| 弊端 | 具体表现 | MES 场景后果 |
|------|---------|-------------|
| **向量相似 ≠ 关系连接** | 物料批号 `M20260707001` 与不良记录文本语义毫不相似，但二者强关联 | 关键链路节点召回不到，追溯断链 |
| **多跳追溯失败** | "物料→供应商→其他批次→产线"需 3+ 跳，向量只能返回 top-k 块 | 无法回答跨工序/跨批次的追溯问题 |
| **chunk 切割破坏链路** | 一条完整追溯链被切成多个独立块，上下游上下文丢失 | 检索片段拼不出完整因果链 |
| **全局归纳无力** | "本月质量问题主题"只能返回相似不良描述 | 无法做主题聚类、全局概览 |
| **影响面/反向遍历缺失** | "设备异常影响哪些工单/客户"是反向图遍历 | 防错召回范围判断失败 |
| **召回靠语义"撞运气"** | 追溯查询常不含答案实体的文字描述 | 召回率不可控，关键节点易漏 |
| **幻觉风险高** | 不相关 chunk 拼给 LLM，模型"脑补"关系 | 误判根因/召回范围，误召回或漏召回后果严重 |
| **实时更新成本高** | MES 工单状态高频变更，传统 RAG 需重建 embedding 索引 | 索引滞后于实时生产状态 |
| **无法判断"路径缺失"** | "这批料未流向哪个工单"需图遍历确认缺失 | 无法支撑防错/隔离判定 |

### 4.3 Graph RAG 对 MES 的契合点

1. **追溯即图遍历**：前向（这批料流向哪）/后向（这台产品用了什么）追溯，图谱天然胜任；
2. **根因分析多跳推理**：跨工序、跨批次、跨供应商的根因定位，靠图遍历而非语义拼接；
3. **影响面排查**：异常设备 → 受影响工单 → 受影响客户，反向遍历一步到位；
4. **增量实时更新**：节点/边可增量写入，匹配 MES 实时状态变更（工单流转、设备启停）；
5. **全局视角**：质量主题归纳、召回范围圈定依赖全局图结构，而非局部相似块。

> **结论**：MES 生产数据是"关系型数据"，传统 RAG 用"语义相似"去检索"关系型数据"，本质错配；Graph RAG 用"图结构"去检索"关系型数据"，才是顺势而为——这正是 MES 追溯/防错/根因场景必须选 Graph RAG 的根本原因。

## 五、一句话决策

- **答案藏在某段话里** → 传统 RAG（快、便宜、够用）
- **答案靠"关系拼出来"** → Graph RAG（追溯、推理、全局归纳）

> 实际工程中常**混合使用**：Graph RAG 做关系推理和路径召回，传统 RAG 补充细节文档块；在 MES 追溯场景下，Graph RAG 的价值远大于传统 RAG。
