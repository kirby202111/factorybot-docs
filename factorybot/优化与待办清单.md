## 🔴 P0 — 安全 & 运行时正确性

### [ ] 1. 租户隔离漏洞链(越权查看/确认编排会话)
- **位置**
  - `app/api/orchestration_router.py:37` `confirm_gate` —— 无 `tenant` 依赖
  - `app/api/orchestration_router.py:48` `get_state` —— 无 `tenant` 依赖
  - `app/api/draft_router.py:26` `GET /draft/{id}/evidence` —— 无 `tenant` 依赖
  - `app/api/schemas.py:68` `ConfirmRequest.user_id = "u_zhang"` —— 默认值可伪造身份
- **问题**:`start` 端点有 `tenant=Depends(tenant_from_headers)`,但 confirm / state / evidence 三端点缺失;叠加 `user_id` 默认 `"u_zhang"`,任意调用方无需认证即可跨租户查看编排状态、确认/驳回 gate、读草稿证据。
- **建议**:三端点统一注入 tenant;service 内(`OrchestrationService.resume` / `get_session`、`DraftService.get_evidence`)按 tenant 校验 session/草稿归属;`user_id` 改必填或从 `X-Tenant-User-Id` header 注入,禁止请求体传入。

### [ ] 2. 后台任务异常静默丢失(两处)
- **位置**
  - `app/infrastructure/obs/observability.py:90` `_safe_async`
  - `app/application/orchestration_service.py:119` `create_task(_drive(...))`
- **问题**:`create_task` 后的 `except` 只捕获创建本身异常,task 内部异常(LlmCallLog 写失败、编排驱动失败)完全不可见,生产"瞎飞"。
- **建议**:`add_done_callback` 中取 `t.exception()` 记 CRITICAL 日志;或统一异常回调封装。

### [ ] 3. 确认令牌双写非原子
- **位置**:`app/infrastructure/redis_/confirmation_store.py:62`
- **问题**:`confirm:{token_id}` 与 `confirm:session:{session_id}:{step}` 两次 `setex` 非原子,中途失败破坏"防重复确认"保证。
- **建议**:Lua 脚本/管道原子写;或反转顺序先写 dedup key(token 写失败仅留无害孤儿)。

### [ ] 4. recursion_limit 猴子补丁可能不生效(需确认)
- **位置**:`app/infrastructure/ai/react_graph.py:125`
- **问题**:`compiled.recursion_limit = recursion_limit` 直接设属性,LangGraph 运行时实际通过 `config={"recursion_limit": N}` 读取。若不生效,诊断/编排始终用默认 25,与 config 的 20/40 不符。
- **建议**:改在 `ainvoke` 处传 `config={"recursion_limit": ...}`;或写测试确认当前 LangGraph 版本是否读取该属性。

### [ ] 5. `assert` 做运行时校验,`python -O` 可绕过
- **位置**:`app/infrastructure/acl/base.py:43,60,86`
- **问题**:用 `assert` 检查 `self._fixtures` / `self._http` 是否就绪,`-O` 模式跳过,mock 下静默变 `AttributeError`。
- **建议**:改 `if x is None: raise RuntimeError(...)`。

### [ ] 6. Kafka 消息未反序列化(real 模式必崩,当前为死代码)
- **位置**:`app/infrastructure/kafka/consumer.py:36`
- **问题**:`AIOKafkaConsumer` 未设 `value_deserializer`,`msg.value` 为 bytes,`.get("event_type")` 抛 `AttributeError`。consumer 目前无人调用,启用前必修。
- **建议**:加 `value_deserializer=lambda v: json.loads(v.decode())`。

### [ ] 25. cost 子系统 7 组件整体悬空(2026-07-15 核实)
- **位置**:`app/infrastructure/cost/`(CacheControl/EarlyStopDetector/PhaseToolBinder/ResultCompactor/ToolResultCache/ModelRouter.route)
- **问题**:五个组件在 `app/` 下零调用,仅 `cost/__init__.py` re-export 与 tests 引用;`ai/` 目录完全不 import cost;`tool_node.py:92` 注释写"可由 ResultCompactor 压缩"但从未调用;ModelRouter 仅 `validate_on_startup()` 接入,`route()` 死代码。整套 token 成本优化是"设计+文档+零上线"。详见根级总览决策 1。
- **建议**:**需拍板**(决策 1):A 接入主流程(route() 接 llm_factory、ResultCompactor 接 ToolNode、EarlyStop 接 ReAct 终止) / B 文档标注未上线 / C 删除代码+下掉《AgentToken成本优化》设计文档。

### [ ] 26. checkpointer real 模式未接线 SqlSaver(Pod 重启丢会话)
- **位置**:`app/infrastructure/persistence/checkpointer.py:18-29`
- **问题**:real 模式(有 mysql_url 且非 mock)下仍返回 `MemorySaver` 仅打 warn,Pod 重启后所有 interrupt/resume 编排会话(含 gate 确认中断态)丢失。注释了 TODO 但是线上风险。
- **建议**:接 `AsyncSqlSaver` 到 lifespan 初始化;或在部署文档明确标注"当前不支持重启恢复编排会话"。

### [ ] 11. LLM 观测指标名/值失真(三处)

## 🟢 P2 — 工程化门禁

### [ ] 19. 缺根 `.gitignore`
- **位置**:`factorybot/`(无 `.gitignore`)
- **问题**:`.env`(含 API Key)、`__pycache__`、`*.pyc` 未忽略,密钥泄露风险。
- **建议**:加 `.env`、`__pycache__/`、`*.pyc`、`.ruff_cache/`、`.mypy_cache/`、`dist/`。

### [ ] 20. 无 CI / lint / type-check
- **位置**:无 `.github/workflows`;`pyproject.toml` 无 `[tool.ruff]` / `[tool.mypy]`;无 `.pre-commit-config.yaml`
- **建议**:加 ruff + mypy 配置 + pre-commit;`.github/workflows/test.yml` 跑 `uv run pytest`。

### [ ] 21. 测试覆盖缺口
- 零 HTTP 层测试(9 文件全直调 service,无 TestClient)
- 无租户隔离测试(全用 `default_tenant` WS-A)
- 编排 SUSPENDED 失败路径无测试(仅 happy path)
- `code_nodes`(barrier / gate / query_compare)无单测
- **建议**:每 router 加 TestClient 冒烟;双租户隔离断言;构造连续失败断言 SUSPENDED;FailureTracker / GateManager 边界单测。

### [ ] 22. 依赖无上限约束
- **位置**:`pyproject.toml`
- **问题**:全 `>=` 无上限,无 lockfile 克隆可能拉 breaking change。
- **建议**:核心依赖加上限(如 `fastapi>=0.110,<1.0`),文档强调 `uv.lock` 必须提交。
