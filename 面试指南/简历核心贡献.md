# 简历 · 核心贡献

> 面向 5 年经验后端开发岗位。基于 `领域模型/` 与 `实现说明/` 文档（不含 Agent/RAG 旁路部分）撰写。
> 量化数据为按后端系统常见量级编造的示例值（与项目设计容量目标同量级），使用时可按真实压测/监控数据替换。

## 核心贡献

**1. 设计并落地 Transactional Outbox + Kafka 可靠消息机制，消除跨服务一致性崩溃窗口**

- **技术动作**：业务状态变更与 `outbox_event` 写入同一本地事务原子提交；Publisher 多实例 `FOR UPDATE SKIP LOCKED` 领取、指数退避重试 + DLT 死信兜底；消费端 `event_id` 幂等（幂等记录与业务处理同事务提交）；`partition_key=聚合根ID` 保序 + 幂等 Producer；生产侧四层限流（领取节流 / 全局令牌桶 / 按 topic 公平 / 在途上限）+ 自适应背压。
- **量化效果**：承载 13 个 topic 命名空间、近百个领域事件；事件投递成功率 99.99%，宕机恢复场景消息丢失为 0；发布延迟 P99 ≤ 300ms；消费重复处理率 < 0.01%（幂等吸收）；批量工单下发（2000+ 事件/分钟）突发下 DB 与 Kafka 集群无击穿。
- **业务影响**：保障"工单下达→过点→完工"跨 6+ 上下文长链路最终一致，消除"状态已变更、下游未感知"导致的流程断裂与人工对账成本。

**2. 主导高并发设备采集链路设计，实现万级报文/秒可靠接入与存储分层**

- **技术动作**：架构级区分高频采集与低频业务事件两条链路（采集明确不走 Outbox）；边缘网关按策略模式实现 SECS/GEM、OPC-UA、Modbus、MQTT 多协议解码；边缘缓冲 + 断点续传（单调游标"先补后新"）；平台 `msg_id` 去重 + 乱序矫正窗口；大载荷（扭矩曲线 / AOI 图像 / 烧录日志）经预签名 PUT 直传 MinIO、主流仅传 URI + sha256；热/温/冷三层存储（Redis 实时快照 + MySQL 温层 + 对象存储冷层）。
- **量化效果**：单网关接入 50 台设备长连接，采集吞吐峰值 1.2 万报文/秒，端到端落库延迟 P99 < 1s；大载荷分流使 Kafka 主流流量下降约 70%；网关断网 30 分钟恢复后数据零丢失，补传去重命中率 99.9%；设备实时数据查询 P99 ≤ 200ms。
- **业务影响**：秒级工艺参数（温区、链速）与单件事件可靠入库，支撑 SPC 分析与全链路追溯；采集压力与过点主链路完全隔离，产线高峰不停产。

**3. 负责过点执行引擎核心设计与实现，达成低延迟、强防错、零分布式事务**

- **技术动作**：过点记录、放行决策、路线推进、工单进度、测试结果五聚合收敛至同一本地事务；六维度并行防错校验 + 四道门禁（设备可用性 / 工艺版本 / 质量门禁 / 首件）；工艺/设备/质量/齐套四类配置数据本地缓存 + 未命中降级 REST 兜底；`routeVersion` 快照绑定实现工艺变更不撕裂在制品；写侧权威 + `WipUnit` 读侧投影（上下文内 CQRS，可从事件流重放重建）。
- **量化效果**：过点全链路 P99 ≤ 200ms（缓存命中主路径）、降级查询 ≤ 500ms；配置缓存命中率 > 99%，换班高峰（单线 50 工位并发扫码）下无超时与缓存雪崩；工艺版本切换时在制品错乱率为 0；过点记录不可变，历史可按当时工艺版本 100% 回放。
- **业务影响**：把"过站瞬间"做成原子业务事务，防错拦截精确到失败维度，从机制上杜绝漏放不良品，满足汽车电子级审计追溯要求。

**4. 构建设备可用性中枢，实现多源阻塞合取重算与一致性强度分级**

- **技术动作**：台账上下文作为可用性唯一权威源，汇聚点检/计量/维修/采集四源事件做 9 维阻塞投影合取重算；区分硬停用（SuspendAsset）、条件不可用（MarkAssetUnavailable）、叠加阻塞（AddBlockingReason）三种语义；同服务强防错场景走本地事务同步、跨服务场景走异步事件；乐观锁 + 多源幂等去重。
- **量化效果**：可用性重算幂等率 100%（并发/重复事件零副作用），乐观锁冲突率 < 0.1%；CRITICAL 故障停机同步延迟 < 50ms（本地事务内完成）；资产状态查询 QPS 2000+、P99 < 20ms；相比单一状态机方案，多阻塞并存场景的维度丢失率降为 0。
- **业务影响**：过点准入硬门禁避免带病/超期设备流入生产；点检超期等合规阻塞不误停物理可用资产，减少非计划停线损失。

**5. 落地工单与排产编排，以业务门禁从源头堵住超产与错版投产**

- **技术动作**：SAP 工单幂等接收；开工前按目标产量等量预生成产品流水号、首工序绑号过点实现超产物理门禁；`KitStatus` 多源物料事件汇聚重算（READY↔NOT_READY 双向可逆 + 去抖合并 + 分区保序）；排产半自动建议 + 计划员确认落槽，排产快照咨询性不门禁过点。
- **量化效果**：超产拦截率 100%（流水号耗尽即物理阻断，无需完工后比对）；批量 BOM 导入（5000+ 事件/分钟）场景去抖合并使齐套重算次数下降约 90%；工单状态机终态拒收，非法流转拦截 100%；排产确认后才锁料，无效物料预占减少约 40%。
- **业务影响**：从入口杜绝超产与错版投产风险，齐套状态实时驱动排产重排，缩短缺料停线等待时间。
