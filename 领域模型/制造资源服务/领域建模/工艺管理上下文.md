# 工艺管理上下文 — 领域建模（Process Management Domain Model）

> **限界上下文**：工艺管理
> **统一语言**：Operation（工序）, ParameterTemplate（参数模板）, RouteVersion（工艺路线版本·聚合根，含步骤序列与生命周期）, RouteStep（路线步骤·RouteVersion 内实体）, AntiErrorItem（防错项·步骤配置）, QualityGateBinding（质量门禁绑定）, EquipmentSpecBinding（设备规格绑定）, FixtureMatchingBinding（工装匹配绑定）, ReentryPoint（再入点）, RealtimeDataCheckConfig（实时数据校验配置）, RouteVersionState（DRAFT/SUBMITTED/ACTIVATED/DEPRECATED/ARCHIVED）, SpecificationKey（规格键·引用台账能力规格）, RouteCache（工艺路线缓存·过点执行上下文本地投影）
> **建模依据**：[事件风暴 — 工艺管理上下文](../事件风暴/工艺管理上下文.md)

---

## 0. 建模总览

本域是制造资源服务下的**配置子域**，是 PCBA + 整机组装混合型车间所有"工艺路线与版本"的权威源。核心职责是管理**工序定义、参数模板、工艺路线编排、版本生命周期、步骤多维绑定、版本生效发布、再入点配置**——即"**工艺怎么定义、版本怎么生效发布、步骤绑定哪些防错/质量/设备/工装规则**"；**不负责**物料主数据与产品 BOM（归物料上下文，本上下文以 `product_id`/`bom_item_ref` 引用）、检验标准与质量门禁规则定义（归质量上下文，本上下文以 `quality_gate_rule_id` 引用）、设备/工装能力规格与匹配规则的事实源（归设备工装台账上下文，本上下文以 `spec_keys`/`fixture_matching_rule_id` 引用）、过点判定与路线推进执行（归过点执行上下文）、在制品位置投影（归在制品追踪上下文）。本上下文是**配置型主数据上下文**，写少读多，对外以"版本生效事件 + 只读规格读模型"为协作契约。

本上下文与过点执行上下文虽分属不同服务（制造资源服务 vs 生产执行服务），但工艺对过点的协作采用"**本地缓存 + 降级查询**"解耦：版本生效后发布 `ProcessRouteActivated`（异步事件，过点执行上下文订阅刷新 `RouteCache`，非强防错阻塞）；过点时缓存未命中降级 REST 查询本上下文 `RouteVersionReadModel`（≤500ms，领域总览 §4.1/§5.1）。本上下文**不主动通知在制品**——在制品按其首次过点锁定的 `routeVersion` 继续（INV-09），版本变更仅影响变更后首次过点的在制品。

## 1. 聚合根

### 1.1 Operation（工序）

**一致性边界**：单个工序定义的身份、能力属性与生命周期状态。

**职责**：定义可复用工序类型（SMT 印刷/SPI/贴片/回流焊/AOI/波峰焊/FCT/烧录/电批锁螺丝/装配/老化/包装）；声明工序能力键（`capability_keys[]`）供步骤规格绑定引用；ACTIVE/DEPRECATED 生命周期。

```yaml
Operation:
  # ─── 标识 ───
  operation_id:    OperationId         # 工序唯一标识（聚合根ID）

  # ─── 属性 ───
  name:            String              # 工序名称
  category:        OperationCategory   # PCBA / ASSEMBLY
  station_type:    StationType         # 工位类型
  capability_keys[]: List<SpecificationKey>  # 工序能力键（供步骤设备规格绑定引用）
  description:     String?

  # ─── 状态 ───
  state:           OperationState      # ACTIVE / DEPRECATED
  deprecated_reason: String?
  deprecated_at:   DateTime?

  # ─── 审计 ───
  defined_by:      String
  defined_at:      DateTime
  updated_at:      DateTime?
```

**行为**：
- `define(name, category, station_type, capability_keys, description, defined_by)` → 发出 `OperationDefined`（前置：`operation_id` 全局唯一 INV-01；→ `ACTIVE`）
- `update(changed_fields, updated_by)` → 发出 `OperationUpdated`（前置：当前 `ACTIVE`；`category` 不可变更 INV-01；触发策略：`FlagAffectedDrafts` 标记引用该工序的 DRAFT 版本 `stale_reference`）
- `deprecate(reason, deprecated_by)` → 发出 `OperationDeprecated`（前置：当前 `ACTIVE`；→ `DEPRECATED`；限制新草稿引用，已生效版本不受影响 INV-04）

> 🔴 **热点：工序与产品/产线的耦合度**（事件风暴 §2.1）——工序是"通用类型"还是按产品族细分？建议立场已固化：**通用工序 + 步骤配置承载产品差异**，避免工序爆炸。`Operation` 只定义通用工序类型，产品差异由 `RouteStep` 的多维绑定承载。待与工艺工程团队确认工序粒度。

> 🔴 **热点：参数模板与台账能力规格的对齐**（事件风暴 §2.1）——本上下文 `ParameterTemplate`（工艺要求值）与台账上下文 `AssetSpecificationProfile`（设备能力上限）是两个视角，过点时由过点执行上下文比较两者。`capability_keys` / `spec_keys` 命名空间需与台账对齐（见 §2.5 `SpecificationKey`）。待与设备工装台账上下文确认 spec_key 字典。

### 1.2 ParameterTemplate（参数模板）

**一致性边界**：单个参数模板的身份、参数键、单位方案与生命周期状态。

**职责**：绑定到 `Operation`；定义工序级参数模板（如回流焊温区曲线、波峰焊链速、电批扭矩）；可复用；ACTIVE/DEPRECATED 生命周期。供步骤配置引用（`ParameterTemplateBinding`）。

```yaml
ParameterTemplate:
  # ─── 标识 ───
  template_id:     ParameterTemplateId  # 参数模板唯一标识（聚合根ID）

  # ─── 关联 ───
  operation_id:    OperationId          # 绑定的工序（INV：绑定唯一工序）

  # ─── 参数 ───
  param_keys[]:    List<String>         # 参数键（如 zone1_temp / chain_speed / torque）
  unit_scheme:     UnitScheme           # 单位方案（温度℃/速度m·min⁻¹/扭矩N·m）
  description:     String?

  # ─── 状态 ───
  state:           ParameterTemplateState  # ACTIVE / DEPRECATED

  # ─── 审计 ───
  defined_by:      String
  defined_at:      DateTime
  updated_at:      DateTime?
```

**行为**：
- `define(operation_id, param_keys, unit_scheme, description, defined_by)` → 发出 `ParameterTemplateDefined`（前置：关联的 `Operation` 非 `DEPRECATED`；→ `ACTIVE`）
- `update(changed_fields, updated_by)` → 发出 `ParameterTemplateUpdated`（前置：当前 `ACTIVE`；影响引用该模板的 DRAFT 版本，已生效版本不受影响 INV-04）

> 参数模板是"工艺要求值"的载体，与台账"设备能力上限"对齐由过点执行上下文比较。模板修订不回写已生效路线版本（INV-04）。

### 1.3 RouteVersion（工艺路线版本）

**一致性边界**：单个路线版本的产品/路线类型绑定、步骤序列、多维绑定与完整生命周期。**本上下文核心聚合根**。

**职责**：为产品 × 产线编排工序步骤序列（PCBA 段/整机组装段）；承载 DRAFT→SUBMITTED→ACTIVATED→DEPRECATED→ARCHIVED 完整状态机；步骤多维绑定（防错/质量门禁/设备规格/工装匹配/参数模板/再入点）；生效后内容不可变（INV-04）；生效发布 `ProcessRouteActivated` 供过点执行上下文刷新缓存。

```yaml
RouteVersion:
  # ─── 标识 ───
  route_version_id: RouteVersionId      # 路线版本唯一标识（聚合根ID）
  route_id:        RouteId              # 逻辑路线标识（同 route 多版本共享，跨版本不变）
  version_no:      Integer              # 版本号（同 route 内递增）

  # ─── 绑定 ───
  product_id:      ProductId            # 引用物料上下文产品（设计时校验存在性）
  route_type:      RouteType            # PCBA / ASSEMBLY（双段分别编排）

  # ─── 步骤序列（聚合内实体，仅 DRAFT 态可变更 INV-04）───
  steps[]:         List<RouteStep>      # 步骤序列（按 step_no 排序）

  # ─── 状态 ───
  state:           RouteVersionState    # DRAFT / SUBMITTED / ACTIVATED / DEPRECATED / ARCHIVED
  effective_at:    DateTime?            # 生效时间（ACTIVATED 时设置）
  superseded_by:   RouteVersionId?      # 被哪个新版本取代（DEPRECATED 时设置；null=整体弃用）
  rejection_notes: String?              # 审核驳回/生效拒绝原因
  activation_blocked_reason: String?    # 生效拒绝原因（回 DRAFT 时携带，🔴 事件风暴 §3）

  # ─── 审计 ───
  created_by:      String
  created_at:      DateTime
  submitted_by:    String?
  submitted_at:    DateTime?
  activated_by:    String?
  deprecated_at:   DateTime?
```

**行为**：
- `create(route_id, product_id, route_type, created_by)` → 发出 `RouteVersionCreated`（前置：产品存在（查物料上下文）；同 `(route_id, route_type)` 无 ACTIVATED 冲突或为显式升级；→ `DRAFT`）
- `configureStep(step_no, operation_id, station_type, is_reentry_point)` → 发出 `RouteStepConfigured`（前置：当前 `DRAFT` INV-04；`operation_id` 非 DEPRECATED）
- `bindAntiErrorItem(step_no, dimension, params)` → 发出 `AntiErrorItemBound`（前置：当前 `DRAFT`；维度见 §2.6）
- `bindQualityGate(step_no, quality_gate_rule_id)` → 发出 `QualityGateBound`（前置：当前 `DRAFT`；规则存在性设计时校验 INV-08）
- `bindEquipmentSpec(step_no, spec_keys[])` → 发出 `EquipmentSpecBound`（前置：当前 `DRAFT`；spec_keys 在台账可解析 INV-08）
- `bindFixtureMatchingRule(step_no, fixture_matching_rule_id)` → 发出 `FixtureMatchingRuleBound`（前置：当前 `DRAFT`；rule_id 存在性设计时校验 INV-08）
- `bindParameterTemplate(step_no, template_id)` → 发出 `ParameterTemplateBound`（前置：当前 `DRAFT`；template 非 DEPRECATED）
- `configureReentryPoint(step_no, reentry_rules)` → 发出 `ReentryPointConfigured`（前置：当前 `DRAFT`；`is_reentry_point=true`）
- `submitReview(submitted_by)` → 发出 `RouteReviewSubmitted`（前置：当前 `DRAFT`；至少 1 步且每步必填绑定满足 INV-06；→ `SUBMITTED`；经 `RouteValidationService` 预校验）
- `activate(activated_by)` → 发出 `ProcessRouteActivated`（前置：当前 `SUBMITTED`；引用校验全通过 INV-07/INV-08；→ `ACTIVATED`；设置 `effective_at`；生效后内容不可变 INV-04；同 `(route_id, route_type)` 唯一 ACTIVE INV-02，经 `RouteActivationService` 同事务弃用旧版本）
- `rejectReview(rejection_notes, rejected_by)` → 发出 `RouteReviewRejected`（前置：当前 `SUBMITTED`；→ `DRAFT`，携带 `rejection_notes`）
- `rejectActivation(failed_refs[])` → 发出 `ActivationRejected`（前置：当前 `SUBMITTED`；主管已批准但生效时引用校验失败；→ `DRAFT`，携带 `activation_blocked_reason`，🔴 事件风暴 §3 热点立场）
- `rejectSubmission(failed_checks[])` → 发出 `ReviewSubmissionRejected`（前置：当前 `SUBMITTED`；提交后预校验失败；→ `DRAFT`）
- `deprecate(reason, superseded_by?, deprecated_by)` → 发出 `ProcessRouteDeprecated`（前置：当前 `ACTIVATED`；→ `DEPRECATED`；设置 `superseded_by`——新版本生效时自动触发则非 null，手动整体弃用则 null；弃用不删除内容 INV-04）
- `archive()` → 发出 `RouteVersionArchived`（前置：当前 `DEPRECATED` 或 `DRAFT`；→ `ARCHIVED`，终态 INV-03）
- `abandonDraft()` → 发出 `RouteVersionArchived`（前置：当前 `DRAFT`；→ `ARCHIVED`，终态；废弃草稿）

> **唯一 ACTIVE 版本是跨实例不变式（INV-02）**：`RouteVersion` 聚合自身无法校验"同 `(route_id, route_type)` 仅一个 ACTIVATED"——这需查询其它版本实例。由 `RouteActivationService` 在生效时查询读模型 + 数据库唯一索引 `(route_id, route_type, status=ACTIVATED)` 共同保证，新版本生效同事务自动 Deprecate 旧版本（outbox）。

> **生效后不可变（INV-04）**：`RouteVersion` 在 `ACTIVATED`/`DEPRECATED`/`ARCHIVED` 态拒收任何 `configureStep`/`bind*` 命令，保证过点执行上下文 `CheckpointRecord.route_version` 快照可永久回溯。步骤与绑定仅在 `DRAFT` 态可变更。

> **审核驳回 vs 生效拒绝的语义区分**（事件风暴 §3）：`RouteReviewRejected`（主管审核环节否决，业务决策）与 `ActivationRejected`（主管已批准但生效时引用校验失败，技术校验）均回 `DRAFT`，但触发阶段与载荷不同。`ActivationRejected` 回 DRAFT 并带 `activation_blocked_reason`（🔴 事件风暴 §3 热点立场：回 DRAFT 而非留 SUBMITTED）。

> 🔴 **热点：是否允许同 route 并存多个 ACTIVATED 版本**（事件风暴 §2.2）——建议立场已固化：**按 `(route_id, route_type)` 维度唯一 ACTIVE**，同一产品同一类型路线同时只能有一个生效版本；不同类型（PCBA/装配）可并存。INV-02。

> 🔴 **热点：DEPRECATED → ARCHIVED 是否要求无在制品引用**（事件风暴 §2.2）——建议立场已固化：**归档不依赖在制品状态**（版本不可变，归档只是标记不再用于新过点；已过点记录与在制品按其锁定的 routeVersion 继续，INV-04/INV-09）。归档后读模型仍可查询。

## 2. 值对象

### 2.1 标识值对象

```yaml
OperationId:         { value: String }    # 工序唯一标识
ParameterTemplateId: { value: String }    # 参数模板唯一标识
RouteVersionId:      { value: String }    # 路线版本唯一标识（聚合根ID）
RouteId:             { value: String }    # 逻辑路线标识（跨版本共享）
ProductId:           { value: String }    # 产品标识（引用物料上下文，经 ACL 翻译）
StepNo:              Integer              # 步序号（RouteVersion 内唯一，从 1 递增）
QualityGateRuleId:   { value: String }    # 质量门禁规则标识（引用质量上下文，经 ACL 翻译）
FixtureMatchingRuleId: { value: String }  # 工装匹配规则标识（引用台账上下文，经 ACL 翻译）
```

> 不可变。`ProductId`/`QualityGateRuleId`/`FixtureMatchingRuleId` 是上下文外引用，经防腐层（ACL）从对应上下文翻译为本上下文语义，本上下文不持有其聚合。引用存在性在 DRAFT 绑定/SUBMITTED 生效时同步 REST 校验（INV-07/INV-08）。

### 2.2 OperationCategory / RouteType / StationType（分类枚举）

```yaml
OperationCategory:
  - PCBA        # PCBA 段工序（印刷/SPI/贴片/回流焊/AOI/波峰焊/FCT/烧录）
  - ASSEMBLY    # 整机组装段工序（锁螺丝/装配/老化/包装）

RouteType:
  - PCBA        # PCBA 段路线
  - ASSEMBLY    # 整机组装段路线

StationType:
  - SMT_PRINT / SPI / PICK_PLACE / REFLOW / AOI / WAVE_SOLDER / FCT / PROGRAMMING
  - SCREW_DRIVING / ASSEMBLY / BURN_IN / PACKAGING
  # （枚举随工序类型扩展，与 Operation 一一对应）
```

> 不可变枚举。`OperationCategory` 一经确定不可变更（INV-01）。双段生产架构：同一产品可有 PCBA 路线与整机装配路线，由 `route_type` 区分；两段在过点执行上下文以单件 `routeVersion` 推进衔接，本上下文不感知段间拼接。

### 2.3 OperationState / ParameterTemplateState（基础对象状态）

```yaml
OperationState:
  - ACTIVE      # 可用，可被新草稿步骤引用
  - DEPRECATED  # 弃用，新草稿不可引用；已生效版本引用不受影响（INV-04）

ParameterTemplateState:
  - ACTIVE
  - DEPRECATED
```

> 不可变枚举。`DEPRECATED` 为终态（不再恢复 ACTIVE，需重新定义）。弃用限制新草稿引用，不回写已生效路线版本（INV-04）。

### 2.4 RouteVersionState（路线版本状态）

```yaml
RouteVersionState:
  - DRAFT       # 草稿，可配置步骤与绑定
  - SUBMITTED   # 已提交审核，待主管决策
  - ACTIVATED   # 已生效，内容不可变（INV-04）
  - DEPRECATED  # 已弃用（被新版本取代或手动整体弃用），内容仍不可变
  - ARCHIVED    # 已归档（终态，INV-03）
```

**状态机**：

```
                         [DRAFT]
                           |
            ┌──────────────┼────────────── AbandonDraft ───────────┐
            │              │                                        │
            │      SubmitRouteReview                                │
            │       (前置: ≥1 步且每步必填绑定满足, INV-06)          │
            │              │                                        │
            │              v                                        │
            │        [SUBMITTED]                                    │
            │              │                                        │
            │     ┌────────┴───────────────┐                        │
            │     v                         v                        │
            │  ActivateRouteVersion      RejectRouteReview           │
            │  (前置: 引用校验通过,        (审核驳回, 回 DRAFT,        │
            │   INV-07/INV-08)            带 rejection_notes)        │
            │     │                         │                        │
            │     │ ActivationRejected       │                        │
            │     │ (主管已批准但生效校验      │                        │
            │     │  失败, 回 DRAFT,          │                        │
            │     │  带 activation_blocked_   │                        │
            │     │  reason, 🔴 §3)           │                        │
            │     │  ←──┐                    │                        │
            │     v     │                    v                        │
            │  [ACTIVATED]              [DRAFT]                       │
            │     │                                                    │
            │     │ DeprecateRouteVersion                               │
            │     │ (新版本生效自动触发 superseded_by≠null              │
            │     │  / 手动整体弃用 superseded_by=null)                 │
            │     v                                                    │
            │  [DEPRECATED]                                            │
            │     │                                                    │
            │     │ ArchiveRouteVersion                                │
            │     v                                                    │
            └─▶ [ARCHIVED] ◀──────────────────────────────────────────┘
                  (终态—之后任何事件均拒收, INV-03)
```

**不变式**：
- `→ DRAFT`（新建）：`create()`，产品存在、同 route 无冲突或显式升级
- `DRAFT → SUBMITTED`：`submitReview()`，前置 ≥1 步且每步必填绑定满足（INV-06）
- `SUBMITTED → ACTIVATED`：`activate()`，前置引用校验通过（INV-07/INV-08）；同 `(route_id, route_type)` 唯一 ACTIVE（INV-02，跨实例）
- `SUBMITTED → DRAFT`：`rejectReview()`/`rejectActivation()`/`rejectSubmission()`，审核驳回/生效拒绝/提交预校验失败
- `ACTIVATED → DEPRECATED`：`deprecate()`，新版本生效自动触发（`superseded_by≠null`）或手动整体弃用（`superseded_by=null`）
- `DEPRECATED → ARCHIVED`：`archive()`，归档不依赖在制品状态（🔴 热点立场）
- `DRAFT → ARCHIVED`：`abandonDraft()`，废弃草稿
- `ARCHIVED` 之后任何事件均拒收（终态 INV-03）
- 状态单向流转，无回退边（驳回是 `SUBMITTED→DRAFT`，属审核流而非回退）

## 3. 领域服务

领域服务封装**跨聚合**的业务逻辑或**不自然归属**单一聚合根的操作。

### 3.1 RouteValidationService（路线版本校验服务）

**职责**：编排引用完整性校验——提交审核时预校验（INV-06）、生效时引用校验（INV-07/INV-08）。校验失败拒绝 `SubmitRouteReview`/`ActivateRouteVersion`，不产生半成品状态。

```yaml
RouteValidationService:
  方法:
    precheckOnSubmit(route_version_id):
      # 提交审核时预校验（INV-06），同步查本上下文 + 上下文外（REST）
      # 1. steps 数 ≥ 1？
      # 2. 每步 operation_id 非 DEPRECATED？（查本上下文）
      # 3. 每步必填防错项齐全？（operation_id + 工位类型 + 必需防错项）
      # 4. 引用对象存在性（quality_gate_rule / spec_keys / fixture_matching_rule / template）？
      #    - 查质量上下文(REST)：quality_gate_rule_id 存在
      #    - 查台账上下文(REST)：spec_keys 可解析、fixture_matching_rule_id 存在
      # 失败 → RouteVersion.rejectSubmission(failed_checks[]) → ReviewSubmissionRejected（回 DRAFT）

    validateOnActivate(route_version_id):
      # 生效时引用校验（INV-07/INV-08），同步查本上下文 + 上下文外（REST）
      # 1. 所有 operation 非 DEPRECATED？（INV-07，查本上下文）
      # 2. 所有上下文外引用可解析存在？（INV-08）
      #    - quality_gate_rule_id 存在（查质量上下文）
      #    - spec_keys 在台账可解析（查台账上下文）
      #    - fixture_matching_rule_id 存在（查台账上下文）
      #    - template_id 非 DEPRECATED（查本上下文）
      # 失败 → RouteVersion.rejectActivation(failed_refs[]) → ActivationRejected（回 DRAFT，🔴 §3）
```

> **为什么不放在聚合根内**：引用校验需查询上下文外（质量上下文/台账上下文）与其它 `Operation`/`ParameterTemplate` 实例——单条 `RouteVersion` 聚合无权跨上下文查询或查询其它聚合实例。校验是跨聚合/跨上下文编排，归本服务。同步 REST 查询不引入分布式事务（校验失败拒绝命令，领域总览 §5.3）。

> 🔴 **热点：是否缓存上下文外引用以加速设计时校验**（事件风暴 §2.5）——建议立场已固化：**当前阶段不维护**本地投影（写少读多场景下设计频次低，同步查询足够；引入投影会增加一致性复杂度）。若后续设计体验差再引入。

### 3.2 RouteActivationService（路线版本生效服务）

**职责**：编排版本生效——校验通过后激活版本、同事务弃用同路线旧版本（INV-02 跨实例）、通过事务发件箱发布 `ProcessRouteActivated` + `ProcessRouteDeprecated`（INV-10）。

```yaml
RouteActivationService:
  方法:
    activate(route_version_id, activated_by):
      # 1. 委托 RouteValidationService.validateOnActivate（INV-07/INV-08）
      #    失败 → rejectActivation → ActivationRejected（回 DRAFT）
      # 2. 加载 RouteVersion → activate(activated_by) → ProcessRouteActivated（→ ACTIVATED）
      # 3. 跨实例唯一 ACTIVE 校验（INV-02）：
      #    查读模型同 (route_id, route_type) 的当前 ACTIVATED 版本
      #    + 数据库唯一索引 (route_id, route_type, status=ACTIVATED)
      # 4. 若存在旧 ACTIVATED 版本 → 同事务 deprecate(superseded_by=新版本) → ProcessRouteDeprecated
      # 5. 事务发件箱（INV-10）：ProcessRouteActivated + ProcessRouteDeprecated 与状态变更同事务 outbox
      # 6. 发布到 process.route.lifecycle
      #    - 过点执行上下文订阅 ProcessRouteActivated → RefreshProcessRouteCache
      #    - 过点执行上下文订阅 ProcessRouteDeprecated → 标记旧版本不可用于新过点
```

> **为什么不放在聚合根内**：唯一 ACTIVE 版本是跨实例不变式（INV-02），单条 `RouteVersion` 无权查询同 route 其它版本实例；自动弃用旧版本是跨聚合编排；事务发件箱发布是跨服务集成。归本服务 + 读模型查询 + 唯一索引共同保证。

> 🔴 **热点：生效事件的载荷大小**（事件风暴 §2.4）——建议立场已固化：**事件载荷只含版本元数据 + 步骤摘要**，过点执行上下文刷新缓存时若需详情再 REST 查询本上下文 `RouteVersionReadModel`。避免长路线（几十步）载荷过大。

> 🔴 **热点：生效发布的事务发件箱**（事件风暴 §2.4，INV-10）——`ProcessRouteActivated` 的发布与 `RouteVersion` 状态变更（SUBMITTED→ACTIVATED）+ 旧版本 Deprecate 在同一数据库事务内通过 outbox 保证至少一次投递，消费端（过点执行上下文）幂等处理（source_event_id 去重）。本上下文不引入分布式事务。

### 3.3 RouteReferenceImpactService（引用影响分析服务）

**职责**：上下文外/本上下文规则弃用时，标记引用该对象的 DRAFT 版本为 `stale_reference`（仅警告，不变更已生效版本 INV-04）。

```yaml
RouteReferenceImpactService:
  方法:
    onQualityGateDeprecated(quality_gate_rule_id):
      # 来源：质量上下文 quality.gate.lifecycle QualityGateDeprecated(superseded_by=null)
      # 1. 幂等去重：(rule_id, version) 去重表
      # 2. 查询引用该 rule_id 的 DRAFT 版本
      # 3. 标记 stale_reference 警告（不变更已生效版本 INV-04）
      # 已生效版本引用仍存在（INV-04 不可变），过点执行上下文读缓存发现规则缺失时走拦截+告警

    onOperationDeprecated(operation_id):
      # 来源：本上下文内部 OperationDeprecated
      # 1. 查询引用该 operation_id 的 DRAFT 版本
      # 2. 标记 stale_reference 警告
      # 已生效版本不受影响（INV-04）

    onParameterTemplateDeprecated(template_id):
      # 同上，标记引用该模板的 DRAFT 版本 stale_reference
```

> **为什么不放在聚合根内**：引用影响分析需跨实例查询所有 DRAFT `RouteVersion`（哪些引用了被弃用的 rule/operation/template）——单条 `RouteVersion` 聚合无权查询其它实例。归本服务 + 读模型查询。已生效版本不变（INV-04），仅 DRAFT 标记警告。

> 🔴 **热点：已生效版本引用的上下文外规则被弃用怎么办**（事件风暴 §2.5）——建议立场已固化：**不回写已生效版本**（INV-04 不可变），由过点执行上下文在过点时读质量门禁缓存发现规则缺失时走拦截 + 告警（HOLD/BLOCK 语义）。本上下文仅对 DRAFT 版本发 `stale_reference` 警告。

> 🔴 **热点：质量门禁规则修订是否需通知本上下文重校验已生效版本**（事件风暴 §8）——建议立场已固化：**规则修订不通知本上下文**（rule_id 不变即引用有效，过点执行上下文读缓存自动反映最新逻辑），仅规则**弃用**（`QualityGateDeprecated superseded_by=null`）才通知标记 DRAFT。

## 4. 应用服务

应用服务是**外部调用入口**，负责：接收请求 / 事务边界 / 调用领域服务编排 / 发布集成事件。本上下文是配置型主数据上下文，与过点执行上下文的协作经**异步事件解耦**（版本生效事件）+ **降级查询**（缓存未命中 REST 查询读模型），不在过点主事务中引入分布式事务（领域总览 §5.3）。

### 4.1 ProcessCommandAppService（工艺命令应用服务）

**职责**：处理工序/参数模板/路线版本的写操作命令（REST/工艺设计器入口，发命令者：工艺工程师/工艺主管）。

```yaml
ProcessCommandAppService:
  方法:
    # ─── 工序与参数模板 ───
    defineOperation(cmd):
      # → Operation.define → 写仓储 → Outbox
      # 幂等：commandId；operation_id 唯一（INV-01）
    updateOperation(cmd):
      # → Operation.update → FlagAffectedDrafts（RouteReferenceImpactService）
    deprecateOperation(cmd):
      # → Operation.deprecate → FlagAffectedDrafts
    defineParameterTemplate(cmd):
      # → ParameterTemplate.define
    updateParameterTemplate(cmd):
      # → ParameterTemplate.update

    # ─── 路线版本 ───
    createRouteVersion(cmd):
      # → RouteVersion.create（产品存在性设计时校验）
    configureStep(route_version_id, step_no, operation_id, station_type, is_reentry_point):
      # → RouteVersion.configureStep（前置 DRAFT INV-04）
    bindAntiErrorItem(route_version_id, step_no, dimension, params):
      # → RouteVersion.bindAntiErrorItem（前置 DRAFT）
    bindQualityGate(route_version_id, step_no, quality_gate_rule_id):
      # → RouteVersion.bindQualityGate（前置 DRAFT；规则存在性设计时校验 INV-08）
    bindEquipmentSpec(route_version_id, step_no, spec_keys[]):
      # → RouteVersion.bindEquipmentSpec（前置 DRAFT；spec_keys 可解析性校验 INV-08）
    bindFixtureMatchingRule(route_version_id, step_no, fixture_matching_rule_id):
      # → RouteVersion.bindFixtureMatchingRule（前置 DRAFT；rule_id 存在性校验 INV-08）
    bindParameterTemplate(route_version_id, step_no, template_id):
      # → RouteVersion.bindParameterTemplate（前置 DRAFT；template 非 DEPRECATED）
    configureReentryPoint(route_version_id, step_no, reentry_rules):
      # → RouteVersion.configureReentryPoint（前置 DRAFT）

    # ─── 审核与生效 ───
    submitRouteReview(route_version_id, submitted_by):
      # → RouteVersion.submitReview → RouteValidationService.precheckOnSubmit（INV-06）
      #   预校验失败同事务 rejectSubmission → ReviewSubmissionRejected（回 DRAFT）
    activateRouteVersion(route_version_id, activated_by):
      # → RouteActivationService.activate（同事务校验 + 激活 + 弃用旧版本 + outbox）
    rejectRouteReview(route_version_id, rejection_notes, rejected_by):
      # → RouteVersion.rejectReview（回 DRAFT）
    deprecateRouteVersion(route_version_id, reason, deprecated_by):
      # → RouteVersion.deprecate（手动整体弃用，superseded_by=null）
    archiveRouteVersion(route_version_id):
      # → RouteVersion.archive（终态 INV-03）
    abandonDraft(route_version_id):
      # → RouteVersion.abandonDraft（→ ARCHIVED）
```

| 用例 | 事务边界 | 调用领域对象 | 产出事件 | 幂等策略 |
|------|----------|--------------|----------|----------|
| 定义工序 | 单聚合事务 | `Operation.define` | `OperationDefined` | `commandId`；`operation_id` 唯一（INV-01） |
| 更新/弃用工序 | 单聚合事务 | `Operation.update`/`deprecate` | `OperationUpdated`/`Deprecated` | `commandId`；`version` |
| 定义/更新参数模板 | 单聚合事务 | `ParameterTemplate.define`/`update` | `ParameterTemplateDefined`/`Updated` | `commandId` |
| 创建路线版本 | 单聚合事务 | `RouteVersion.create` | `RouteVersionCreated` | `commandId`；产品存在性设计时校验 |
| 配置步骤/绑定 | 单聚合事务 | `RouteVersion.configureStep`/`bind*` | `RouteStepConfigured`/`*Bound` | `commandId`；前置 DRAFT（INV-04） |
| 提交审核 | 单聚合事务 | `RouteVersion.submitReview` + `RouteValidationService.precheckOnSubmit` | `RouteReviewSubmitted`/`ReviewSubmissionRejected` | `commandId`；INV-06 |
| 生效版本 | 版本 + 旧版本同事务 | `RouteActivationService.activate` | `ProcessRouteActivated` + `ProcessRouteDeprecated`（旧版本） | `commandId`；INV-02/07/08/10 |
| 审核驳回 | 单聚合事务 | `RouteVersion.rejectReview` | `RouteReviewRejected` | `commandId` |
| 弃用/归档/废弃草稿 | 单聚合事务 | `RouteVersion.deprecate`/`archive`/`abandonDraft` | `ProcessRouteDeprecated`/`RouteVersionArchived` | `commandId`；终态拒收（INV-03） |

> **生效版本用例的事务边界**扩展为「RouteVersion 状态变更 + 旧版本 Deprecate + Outbox 同事务」（INV-02/INV-10）。校验失败（INV-07/INV-08）则 `rejectActivation` 回 DRAFT，不产生半成品状态。

### 4.2 ProcessEventConsumeAppService（事件消费应用服务）

**职责**：订阅上下文外事件，翻译为本上下文命令，委托领域服务处理（事件风暴 §2.5 消费策略）。本上下文以发布为主、消费为辅，订阅事件极少（已生效版本不可变 INV-04，上下文外规则变更不回写已生效版本）。

```yaml
ProcessEventConsumeAppService:
  订阅主题与处理:
    # 质量上下文（主题前缀 quality.*）
    quality.gate.lifecycle (QualityGateDeprecated, superseded_by=null):
      → RouteReferenceImpactService.onQualityGateDeprecated
      # 仅标记引用该规则的 DRAFT 版本 stale_reference（INV-04 保证已生效版本不变）
      # 幂等：(rule_id, version) 去重表
```

> **不直接消费上下文外"修订"事件**（事件风暴 §8 热点立场）：规则修订（`QualityGateRuleActivated`，rule_id 不变）不通知本上下文，过点执行上下文读缓存自动反映最新逻辑；仅规则**弃用**（`superseded_by=null`）才标记 DRAFT。

> **上下文外事件只消费不重发**（INV-11）：本上下文将订阅事件包装为本上下文语义事件（如 `OperationDeprecated` 内部事件触发 `FlagAffectedDrafts`）后处理，下游凭主题前缀区分来源。

> **主题命名约定**：本域**对外发布**使用 `process.*` 前缀。本域**订阅**使用各发布域实际前缀（`quality.*`），不重写。**设计时同步校验查询**（REST，非事件订阅）：产品/BOM 存在性 ← 物料上下文；质量门禁规则存在性 ← 质量上下文；spec_keys 可解析性 / fixture_matching_rule ← 台账上下文（`eam.*`）。

### 4.3 ProcessQueryAppService（查询应用服务）

**职责**：提供读模型查询，支撑过点执行上下文降级查询、工艺设计器、数据应用上下文。

```yaml
ProcessQueryAppService:
  方法:
    getRouteVersion(route_version_id):              RouteVersionReadModel
    getActiveRouteVersion(route_id, route_type):     RouteVersionReadModel?   # 当前生效版本
    listRouteVersionsByProduct(product_id):          List<RouteVersionSummaryDTO>
```

## 6. 不变规则（Invariants）

不变规则是领域模型中**必须始终为真**的业务约束，无论经过何种操作序列。

### 6.1 工序与参数模板不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-01 | `operation_id` 全局唯一；`OperationCategory` 一经确定不可变更；DEPRECATED 后新草稿不可引用，已生效版本引用不受影响（INV-04） | `Operation.define` 前置 + `category` 不可变；DEPRECATED 限制新草稿，不回写已生效版本 |

### 6.2 路线版本状态不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-02 | 同 `(route_id, route_type)` 同时仅一个 ACTIVATED 版本 | **跨实例**，由 `RouteActivationService` 在生效时查询读模型 + 数据库唯一索引 `(route_id, route_type, status=ACTIVATED)` 共同保证；新版本生效自动 Deprecate 旧版本（同事务 outbox） |
| INV-03 | `ARCHIVED` 为终态，之后任何事件均拒收 | `RouteVersionState` 状态机；允许从 DEPRECATED / DRAFT 转入 |
| INV-04 | ACTIVATED 后步骤内容与所有绑定不可变（保证过点记录 routeVersion 快照完整性） | `RouteVersion` 在 ACTIVATED/DEPRECATED/ARCHIVED 态拒收任何 `configureStep`/`bind*` 命令；保证过点执行上下文 `CheckpointRecord.route_version` 快照可永久回溯 |
| INV-06 | 提交审核前置：至少 1 步且每步必填绑定满足（operation_id + 工位类型 + 必需防错项） | `RouteVersion.submitReview` 前置 + `RouteValidationService.precheckOnSubmit`（INV-06） |
| INV-07 | 生效前置：所有 operation 非 DEPRECATED | `RouteValidationService.validateOnActivate`（查本上下文） |
| INV-08 | 生效前置：所有上下文外引用（quality_gate_rule_id / spec_keys / fixture_matching_rule_id / template_id）可解析存在 | `RouteValidationService.validateOnActivate`（同步 REST 查询质量/台账上下文 + 本上下文），校验失败拒绝 ActivateRouteVersion，不产生半成品状态 |

### 6.3 跨上下文协作与一致性不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-09 | 版本一致性——工艺版本变更仅影响变更后首次过点的在制品；已过点的在制品按其 `CheckpointRecord.route_version` 继续推进，不受新版本影响（领域总览 §5.1） | 跨上下文，本上下文发布 `ProcessRouteActivated` + 过点执行上下文 `RouteCache` 投影 + `CheckpointRecord.route_version` 快照，由过点引擎在首次过点时固化版本保证（主责在过点执行上下文）。与物料上下文 INV-09、质量上下文 INV-09 跨上下文语义同构、统一编号 |
| INV-10 | 事务发件箱至少一次投递——`ProcessRouteActivated`/`ProcessRouteDeprecated` 的发布与 RouteVersion 状态变更 + 旧版本 Deprecate 在同一数据库事务内通过 outbox 保证，消费端幂等处理（领域总览 §5.4） | outbox 模式 + 消费端幂等（source_event_id 去重表，过点执行上下文侧保证）。与物料上下文 INV-10、质量上下文 INV-10 跨上下文语义同构、统一编号 |
| INV-11 | 上下文外事件只消费不重发——本上下文将订阅事件包装为本上下文语义事件后处理，下游凭主题前缀区分来源 | `ProcessEventConsumeAppService` 包装处理；主题前缀 `process.*` vs `quality.*`/`material.*`/`eam.*`。本上下文以发布为主、消费为辅（仅消费 `QualityGateDeprecated`） |
| INV-12 | 上下文外事件消费幂等——`consumed_event` 表 + 业务键去重 | `RouteReferenceImpactService` 按 `(rule_id, version)` 去重；通用 `consumed_event` 表保证 |
| INV-13 | 版本生效与过点执行经异步事件解耦 + 降级查询不引入分布式事务——本上下文发布 `ProcessRouteActivated` 后不直接调用过点执行上下文刷新接口；过点缓存未命中时 REST 查询 `RouteVersionReadModel`（≤500ms），校验/查询失败不阻塞过点主事务（领域总览 §5.3） | 区别于过点执行上下文内部同步门禁；配置型主数据写少读多，版本生效是独立发布事务，不在过点主事务内同步 |

## 9. 领域服务与应用服务的关系

```
┌──────────────────────────────────────────────────────────────────────┐
│                           外部调用入口                                  │
│                                                                      │
│  REST/工艺设计器 ──▶ ProcessCommandAppService (应用服务)               │

│                      ├─ 跨聚合编排：委托领域服务（校验/生效/引用影响）    │
│                      └─ 同事务推进状态 + 发布集成事件（outbox）          │
│                                                                      │
│  消息消费 ───▶ ProcessEventConsumeAppService (应用服务)                │
│                 └─ 翻译 quality.* 事件 → 委托 RouteReferenceImpactService│

│                                                                      │
│  查询请求 ───▶ ProcessQueryAppService (应用服务，读模型)               │
│                 └─ 直接查询读模型投影（含过点降级查询 ≤500ms）          │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           领域服务层                                    │
│  RouteValidationService │ RouteActivationService │ RouteReferenceImpactService│
│  └─ 封装跨聚合规则，加载聚合，调用聚合行为，写仓储，返回领域事件           │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           聚合根（领域层）                              │
│  Operation / ParameterTemplate / RouteVersion                        │
│  └─ 表达业务状态、行为、不变式、领域事件；不依赖 Spring/MQ/HTTP          │
└──────────────────────────────────────────────────────────────────────┘
```

**原则**：
- 应用服务不包含业务逻辑，只做编排和事务边界（CLAUDE.md 分层）
- 领域服务封装跨聚合的业务规则，每个领域服务必答"为什么不放在聚合根内"
- 聚合根内的业务逻辑由聚合根自身保证，行为是业务动词方法（非 `update/save` 流水账）
- 不变式由聚合根 + 领域服务 + 唯一索引/事件去重表共同守护
- 版本生效与过点执行经异步事件解耦 + 降级查询（INV-13），不在过点主事务中引入分布式事务
