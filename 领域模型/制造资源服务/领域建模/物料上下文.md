# 物料上下文 — 领域建模（Material Domain Model）

> **限界上下文**：物料
> **统一语言**：Material（物料主数据）, Product（产品）, Bom（产品 BOM·版本化）, BomItem（BOM 明细项·Bom 内实体）, BomSubstituteBinding（BOM 替代料绑定）, Supplier（供应商）, SubstituteRule（替代料规则）, Inventory（库存事实·按 part_no × location）, InventoryReservation（齐套预占）, MaterialChange（换料事件）, KitAvailability（齐套可用性投影·供在制品追踪消费）, MaterialCategory（RAW_COMPONENT/SUBASSEMBLY/FINISHED_GOOD/AUXILIARY）, BomVersionState（DRAFT/SUBMITTED/ACTIVATED/DEPRECATED/ARCHIVED）, Location（库位·车间/产线/线边仓三级）
> **建模依据**：[事件风暴 — 物料上下文](../事件风暴/物料上下文.md)

> **变更说明（2026-07-08）**：§6 不变式由主题式单段 `INV-XX` 拆为三段--聚合不变式 `INV-XX`（按聚合根分子节归位）、业务不变式 `BIZ-XX`（本上下文跨聚合 / 跨实例，最终一致）、跨上下文不变式 `INV-CX`（跨限界上下文）。旧 `INV-XX` 归类迁移：聚合内（INV-01/03/04/06/07/08/13）保留原号；跨聚合 / 跨实例（旧 INV-02/14/15/16/18 + INV-01 的 part_no 子项）-> `BIZ-01..06`；跨上下文（旧 INV-09/10/17/19）-> `INV-CX-01..04`。正文内联引用同步更新。事件风暴侧已降级为无编号"已识别约束"清单，编号权威以本节 §6 为准。

## 0. 建模总览

本域是制造资源服务下的**主数据与库存事实子域**，是 PCBA + 整机组装混合型车间所有"物料是什么、BOM 怎么配、库存有多少、够不够齐套开工"的权威源。核心职责管理两类问题：**(1) 配置问题**——物料主数据、产品、BOM 版本、供应商、替代料规则的定义与发布；**(2) 事实问题**——库存入库/消耗/齐套预占/释放，作为在制品追踪上下文齐套判定的事实源。即"**物料是什么、BOM 怎么配、替代料怎么换、库存有多少且够不够齐套**"；**不负责**工序定义与工艺路线编排（归工艺管理上下文，本上下文以 `product_id`/`bom_item_ref` 被其引用）、检验标准与质量门禁规则（归质量上下文）、过点判定与防错校验执行（归过点执行上下文，本上下文仅发布 BOM/替代料/库存事件供其读模型消费）、在制品位置投影与齐套判定（归在制品追踪上下文，本上下文仅发布齐套相关事件供其重算 `KitStatus`）、首件检验流程编排（归首件处理上下文，本上下文仅发布换料事件触发首件）。本上下文是**配置型主数据 + 库存事实源**混合上下文，写少读多（主数据）与中频写入（库存进出）并存，对外以"BOM 生效事件 + 替代料规则事件 + 库存变更事件 + 齐套预占/释放事件 + 换料事件"为协作契约。

本上下文与在制品追踪上下文、过点执行上下文虽分属不同服务，但物料对它们的协作经**异步事件解耦**：BOM 生效/库存变更/替代料生效/齐套预占/释放/换料均发布事件供下游消费，不直接调用下游接口。物料消耗**不在过点主事务内**——过点执行上下文发布 `CheckpointReleased`（过点放行），本上下文消费后按 BOM 异步扣减库存（最终一致，秒级延迟，领域总览 §5.3），保证过点主事务不被跨服务阻塞。物料防错读模型由过点执行上下文订阅 `material.bom.lifecycle`/`material.substitute.lifecycle` 维护本地缓存，缓存未命中降级 REST 查询本上下文 `BomReadModel`/`SubstituteRuleReadModel`（≤500ms）。

## 1. 聚合根

### 1.1 Material（物料主数据）

**一致性边界**：单个物料主数据的身份、分类、规格属性与生命周期状态。

**职责**：定义可复用物料（元器件/半成品/成品/辅料）；`part_no` 全局唯一；`category` 一经确定不可变更；ACTIVE/DEPRECATED 生命周期；登记换料事件发布 `MaterialChanged`（首件触发）。

```yaml
Material:
  # ─── 标识 ───
  part_no:       PartNo               # 物料编码（聚合根ID，全局唯一 BIZ-01）
  name:          String
  category:      MaterialCategory     # RAW_COMPONENT / SUBASSEMBLY / FINISHED_GOOD / AUXILIARY（不可变更 INV-01）
  spec:          String               # 规格
  unit:          String               # 计量单位
  supplier_id:   SupplierId?          # 关联供应商（可选）

  # ─── 状态 ───
  state:         MaterialState        # ACTIVE / DEPRECATED
  deprecated_reason: String?
  deprecated_at: DateTime?

  # ─── 审计 ───
  registered_by: String
  registered_at: DateTime
  updated_at:    DateTime?
```

**行为**：
- `register(name, category, spec, unit, supplier_id?, registered_by)` -> 发出 `MaterialRegistered`（前置：`part_no` 全局唯一 BIZ-01；-> `ACTIVE`）
- `update(changed_fields, updated_by)` -> 发出 `MaterialUpdated`（前置：当前 `ACTIVE`；`category` 不可变更 INV-01；触发策略：`FlagAffectedDrafts` 标记引用该物料的 DRAFT BOM `stale_reference`）
- `deprecate(reason, deprecated_by)` -> 发出 `MaterialDeprecated`（前置：当前 `ACTIVE`；-> `DEPRECATED`；限制新 BOM 草稿引用，已生效 BOM 不受影响 INV-04；不再允许新入库）
- `registerMaterialChange(work_order_id, line_id, change_type, old_part_no?, new_part_no?, substitute_rule_id?, changed_by)` -> 发出 `MaterialChanged`（前置：当前 `ACTIVE`；换料事件发布，供首件处理上下文触发首件）

> 🔴 **热点：物料编码方案**（事件风暴 §2.1）——建议立场已固化：**单一内部料号 + 供应商料号作为属性**，避免重码冲突；与 ERP 物料编码对齐归本上下文的 ERP 物料主数据适配层（ACL）。`part_no` 为内部料号。

> 🔴 **热点：物料分类的粒度**（事件风暴 §2.1）——建议立场已固化：`category` 保持四分类，辅料（锡膏/红胶/清洗剂）消耗差异通过 `BomItem.consumption_rule`（§2.6）表达，不在物料分类层细分。

### 1.2 Product（产品）

**一致性边界**：单个产品的身份、类型与生命周期状态。

**职责**：建档产品（PCBA 产品/整机产品）；关联 BOM；ACTIVE/DEPRECATED 生命周期。供工艺管理上下文以 `product_id` 引用。

```yaml
Product:
  # ─── 标识 ───
  product_id:    ProductId            # 产品唯一标识（聚合根ID）
  name:          String
  type:          ProductType          # PCBA / ASSEMBLY
  category:      MaterialCategory     # 产品类别

  # ─── 状态 ───
  state:         ProductState         # ACTIVE / DEPRECATED

  # ─── 审计 ───
  registered_by: String
  registered_at: DateTime
  updated_at:    DateTime?
```

**行为**：
- `register(name, type, category, registered_by)` -> 发出 `ProductRegistered`（前置：`product_id` 全局唯一；-> `ACTIVE`；供工艺管理上下文引用）
- `update(changed_fields, updated_by)` -> 发出 `ProductUpdated`（触发 `FlagAffectedDrafts` 标记 DRAFT BOM）
- `deprecate(reason)` -> 发出 `ProductDeprecated`（限制新 BOM 草稿；已生效 BOM/工艺不受影响）

> 双段生产架构：PCBA 段 BOM（元器件为主）与整机组装段 BOM（结构件/线缆/软件包为主）分别编排，同一产品可有 PCBA BOM 与整机装配 BOM，由 `bom_type` 区分（§1.3）。

### 1.3 Bom（产品 BOM·版本化）

**一致性边界**：单个 BOM 版本的产品/类型绑定、BomItem 明细与替代料绑定、完整生命周期。**本上下文核心配置聚合根**。

**职责**：编排产品 BOM 明细（BomItem）；承载 DRAFT->SUBMITTED->ACTIVATED->DEPRECATED->ARCHIVED 完整状态机（与工艺管理 RouteVersion 同构）；生效后内容不可变（INV-04）；生效发布 `BomActivated` 供在制品追踪重算 KitStatus + 过点执行刷新物料防错缓存。

```yaml
Bom:
  # ─── 标识 ───
  bom_version_id: BomVersionId        # BOM 版本唯一标识（聚合根ID）
  product_id:    ProductId            # 引用产品
  bom_type:      BomType              # PCBA / ASSEMBLY（双段分别编排）
  version_no:    Integer              # 版本号（同 product × bom_type 内递增）

  # ─── 明细（聚合内实体，仅 DRAFT 态可变更 INV-04）───
  items[]:       List<BomItem>        # BOM 明细项

  # ─── 状态 ───
  state:         BomVersionState      # DRAFT / SUBMITTED / ACTIVATED / DEPRECATED / ARCHIVED
  effective_at:  DateTime?
  superseded_by: BomVersionId?        # 被哪个新版本取代（DEPRECATED 时；null=整体弃用）
  rejection_notes: String?

  # ─── 审计 ───
  created_by:    String
  created_at:    DateTime
  submitted_by:  String?
  submitted_at:  DateTime?
  activated_by:  String?
  deprecated_at: DateTime?
```

**行为**：
- `create(product_id, bom_type, created_by)` -> 发出 `BomVersionCreated`（前置：产品存在；同 `(product_id, bom_type)` 无 ACTIVATED 冲突或为显式升级；-> `DRAFT`）
- `addBomItem(part_no, qty_per_unit, consumption_rule, reference_designators[], updated_by)` -> 发出 `BomItemAdded`（前置：当前 `DRAFT` INV-04；`part_no` 非 DEPRECATED）
- `bindSubstitute(bom_item_key, substitute_rule_id, updated_by)` -> 发出 `SubstituteBound`（前置：当前 `DRAFT`；`SubstituteRule` 存在且有效 INV-08）
- `submitReview(submitted_by)` -> 发出 `BomReviewSubmitted`（前置：当前 `DRAFT`；至少 1 项 BomItem 且每项 part_no 非 DEPRECATED INV-06；-> `SUBMITTED`；经 `BomValidationService` 预校验）
- `activate(activated_by)` -> 发出 `BomActivated`（前置：当前 `SUBMITTED`；引用校验全通过 INV-07/INV-08；-> `ACTIVATED`；设置 `effective_at`；生效后内容不可变 INV-04；同 `(product_id, bom_type)` 唯一 ACTIVE BIZ-02，经 `BomActivationService` 同事务弃用旧版本）
- `rejectReview(rejection_notes, rejected_by)` -> 发出 `BomReviewRejected`（前置：当前 `SUBMITTED`；-> `DRAFT`）
- `rejectActivation(failed_refs[])` -> 发出 `ActivationRejected`（前置：当前 `SUBMITTED`；生效校验失败；-> `DRAFT`）
- `rejectSubmission(failed_checks[])` -> 发出 `BomReviewSubmissionRejected`（前置：当前 `SUBMITTED`；提交预校验失败；-> `DRAFT`）
- `deprecate(reason, superseded_by?, deprecated_by)` -> 发出 `BomDeprecated`（前置：当前 `ACTIVATED`；-> `DEPRECATED`；弃用不删除内容 INV-04）
- `archive()` -> 发出 `BomVersionArchived`（前置：当前 `DEPRECATED` 或 `DRAFT`；-> `ARCHIVED`，终态 INV-03）
- `abandonDraft()` -> 发出 `BomVersionArchived`（前置：当前 `DRAFT`；-> `ARCHIVED`，终态）

> **唯一 ACTIVE 版本是跨实例不变式（BIZ-02）**：`Bom` 聚合自身无法校验"同 `(product_id, bom_type)` 仅一个 ACTIVATED"——由 `BomActivationService` 在生效时查询读模型 + 数据库唯一索引 `(product_id, bom_type, status=ACTIVATED)` 共同保证，新版本生效同事务自动 Deprecate 旧版本（outbox）。

> **生效后不可变（INV-04）**：`Bom` 在 `ACTIVATED`/`DEPRECATED`/`ARCHIVED` 态拒收任何 `addBomItem`/`bindSubstitute` 命令，保证过点执行上下文 `CheckpointRecord` 的 BOM 快照可永久回溯。BomItem 与替代料绑定仅在 DRAFT 态可变更。

> 🔴 **热点：是否允许同 product 并存多个 ACTIVATED BOM 版本**（事件风暴 §2.2）——建议立场已固化：**按 `(product_id, bom_type)` 维度唯一 ACTIVE**，与工艺管理上下文 RouteVersion 的 `(route_id, route_type)` 维度一致。BIZ-02。

> 🔴 **热点：BOM 生效事件的载荷大小**（事件风暴 §2.2）——建议立场已固化：**事件载荷只含版本元数据 + items 摘要**，在制品追踪上下文重算 KitStatus 时若需详情再 REST 查询本上下文 `BomReadModel`。

### 1.4 Supplier（供应商）

**一致性边界**：单个供应商的身份、资质与生命周期状态。

**职责**：供应商建档、资质维护、变更；ACTIVE/DEPRECATED 生命周期。供 `Material.supplier_id` 引用。

```yaml
Supplier:
  supplier_id:    SupplierId          # 供应商唯一标识（聚合根ID）
  name:           String
  qualifications[]: List<String>      # 资质
  state:          SupplierState       # ACTIVE / DEPRECATED
  registered_by:  String
  registered_at:  DateTime
  updated_at:     DateTime?
```

**行为**：
- `register(name, qualifications[], registered_by)` -> 发出 `SupplierRegistered`（-> `ACTIVE`）
- `update(changed_fields, updated_by)` -> 发出 `SupplierUpdated`
- `deprecate(reason)` -> 发出 `SupplierDeprecated`（DEPRECATED 后物料供应商标记需迁移）

### 1.5 SubstituteRule（替代料规则）

**一致性边界**：单条替代料规则的主料×替代料映射、优先级、有效期与生命周期。

**职责**：定义主料与替代料的映射（全局规则）；生效/失效生命周期；不支持多级替代链（当前阶段）。供 `BomSubstituteBinding` 引用到具体 BomItem（两层结构）。

```yaml
SubstituteRule:
  # ─── 标识 ───
  rule_id:           SubstituteRuleId   # 规则唯一标识（聚合根ID）
  primary_part_no:   PartNo             # 主料
  substitute_part_nos[]: List<PartNo>   # 替代料清单
  priority:          Integer            # 优先级（多替代料的优先顺序）

  # ─── 有效期 ───
  valid_from:        DateTime?
  valid_until:       DateTime?

  # ─── 状态 ───
  state:             SubstituteRuleState  # DEFINED / ACTIVATED / DEACTIVATED

  # ─── 审计 ───
  defined_by:        String
  defined_at:        DateTime
  activated_at:      DateTime?
```

**行为**：
- `define(primary_part_no, substitute_part_nos[], priority, valid_from?, valid_until?, defined_by)` -> 发出 `SubstituteRuleDefined`（前置：`primary_part_no` 与 `substitute_part_nos[]` 均 ACTIVE；不支持多级替代链；-> `DEFINED`）
- `activate(activated_by)` -> 发出 `SubstituteRuleActivated`（前置：当前 `DEFINED`；-> `ACTIVATED`；设置 `activated_at`/`valid_from`；发布到 `material.substitute.lifecycle` 供在制品追踪重算 KitStatus + 过点执行刷新物料防错缓存）
- `deactivate(reason)` -> 发出 `SubstituteRuleDeactivated`（前置：当前 `ACTIVATED`；到期或手动；-> `DEACTIVATED`；发布到 `material.substitute.lifecycle`；不再允许新换料引用）
- `update(changed_fields, updated_by)` -> 发出 `SubstituteRuleUpdated`（前置：当前 `DEFINED`；仅 DEFINED 态可改，已激活规则修订走重新定义+激活）

> 🔴 **热点：替代料规则与 BOM 的绑定层级**（事件风暴 §2.3）——建议立场已固化：**两层结构**——`SubstituteRule` 为全局主料×替代料映射；BOM 通过 `BomSubstituteBinding` 引用规则到具体 BomItem（与工艺管理上下文步骤绑定模式同构）。既支持全局规则复用，又支持 BOM 项级细粒度控制。

> 🔴 **热点：替代料优先级与多级替代**（事件风暴 §2.3）——建议立场已固化：**当前阶段不支持多级链**（避免循环与计算复杂），仅支持主料->替代料单级，`priority` 字段表达多替代料的优先顺序。多级替代待后续需求明确后扩展。

### 1.6 Inventory（库存事实）

**一致性边界**：单个 `part_no × location` 维度的库存事实（可用量、锁定量）。**本上下文事实型核心聚合根**。

**职责**：维护可用库存（`available_qty`）与锁定库存（`locked_qty`）；入库/消耗/预占/释放；库存变更驱动在制品追踪上下文重算 `KitStatus`。

```yaml
Inventory:
  # ─── 标识 ───
  part_no:        PartNo              # 物料编码
  location:       Location            # 库位（车间/产线/线边仓三级）
  # 复合主键：(part_no, location)

  # ─── 库存量 ───
  available_qty:  Integer             # 可用库存（允许为负但告警，INV-13 🔴）
  locked_qty:     Integer             # 锁定库存（齐套预占）

  # ─── 批次追溯（可选）───
  lot_no:         String?             # 批次号
  supplier_id:    SupplierId?

  # ─── 审计 ───
  last_received_at: DateTime?
  last_consumed_at: DateTime?
```

**行为**：
- `receive(received_qty, lot_no?, supplier_id?, source, source_event_id?)` -> 发出 `InventoryReceived` + `InventoryChanged`（前置：`part_no` 非 DEPRECATED；`available_qty` 递增；幂等按 `source_event_id` 去重 BIZ-03）
- `consume(consumed_qty, work_order_id, sn, source_event_id, from_locked)` -> 发出 `MaterialConsumed` + `InventoryChanged`（前置：物料消耗最终一致，由 `InventoryConsumptionService` 编排；`from_locked=true` 扣减 `locked_qty`（已预占），`from_locked=false` 扣减 `available_qty`（未预占）；幂等按 `(sn, work_order_id, source_event_id)` 去重 BIZ-04；超扣则 `available_qty` 为负并告警 INV-13）
- `lock(required_qty, work_order_id)` -> 配合 `InventoryReservation` 预占，`locked_qty` 递增（由 `InventoryReservationService` 编排）
- `unlock(released_qty, work_order_id, reason)` -> 配合 `InventoryReservation` 释放，`locked_qty` 递减

> 🔴 **热点：负库存的处理**（事件风暴 §2.4.2）——建议立场已固化：**允许负库存但告警**——过点防错校验在过点执行上下文侧基于本地库存缓存判定（可能因延迟放过），本上下文扣减时若超扣则记 `available_qty` 为负并发布告警，由物控人工补料/盘点。禁止扣减会逼出跨服务事务回滚过点，违反领域总览 §5.3。INV-13。

> 🔴 **热点：预占与消耗的衔接**（事件风暴 §2.4.3）——建议立场已固化：**直接扣减 `locked_qty`**（预占即已锁定，消耗时 `locked_qty` 递减，`available_qty` 不变），避免释放+扣减两步操作的中间态。未预占的消耗直接扣 `available_qty`。`consume(from_locked)` 参数区分两种路径。

### 1.7 InventoryReservation（齐套预占）

**一致性边界**：单个 `work_order_id × part_no × location` 维度的齐套预占生命周期。

**职责**：派工/开工时锁定库存（`locked_qty`）；过点完成消耗或工单取消时释放；预占/释放驱动在制品追踪重算 `KitStatus`。

```yaml
InventoryReservation:
  # ─── 标识 ───
  reservation_id:   ReservationId     # 预占唯一标识（聚合根ID）
  work_order_id:    WorkOrderId       # 工单
  part_no:          PartNo            # 物料
  location:         Location          # 锁定到的具体线边仓（🔴 §2.4.3 按 location 锁定）
  reserved_qty:     Integer           # 预占量

  # ─── 状态 ───
  state:            ReservationState  # RESERVED / RELEASED
  release_reason:   ReservationReason?  # CONSUMED / CANCELLED（释放时必填）

  # ─── 审计 ───
  reserved_at:      DateTime
  released_at:      DateTime?
  source_event_id:  String?           # 来源事件ID（幂等去重键）
```

**行为**：
- `reserve(work_order_id, part_no, location, reserved_qty, source_event_id?)` -> 发出 `KitReserved`（前置：库存齐套，`locked_qty` 递增；同 `(work_order_id, part_no, location)` 预占不重复创建 BIZ-05，跨实例由 `InventoryReservationService` + 唯一索引保证；-> `RESERVED`；部分缺料则 `KitReservationFailed`）
- `release(reason, source_event_id?)` -> 发出 `KitReleased`（前置：当前 `RESERVED`；`reason` 必填（CONSUMED/CANCELLED）；`locked_qty` 递减；-> `RELEASED`；幂等按 `(work_order_id, source_event_id)` 去重 BIZ-05）

> 🔴 **热点：是否在本上下文做齐套预占**（事件风暴 §2.4.3）——建议立场已固化：**做预占**——库存事实源在物料上下文，预占是库存的锁定状态（`locked_qty`），归物料上下文最自然。在制品追踪上下文的 `KitStatus` 判定消费本上下文的 `material.kit.reserved`/`material.kit.released` 事件重算，不重复维护锁定逻辑。

> 🔴 **热点：预占的粒度与位置**（事件风暴 §2.4.3）——建议立场已固化：**按 `location` 锁定**——不同产线的线边仓库存独立，预占应锁定到具体产线的线边仓，避免跨仓挪用。复合键 `(work_order_id, part_no, location)`。BIZ-05。

### 2.4 BomVersionState（BOM 版本状态）

```yaml
BomVersionState:
  - DRAFT            # 草稿，可添加 BomItem 与替代料绑定
  - SUBMITTED        # 已提交审核，待主管决策
  - ACTIVATED        # 已生效，内容不可变（INV-04）
  - DEPRECATED       # 已弃用（被新版本取代或手动整体弃用），内容仍不可变
  - ARCHIVED         # 已归档（终态，INV-03）
```

**状态机**（与工艺管理上下文 `RouteVersionState` 同构）：

```
                         [DRAFT]
                           |
            ┌──────────────┼────────────── AbandonDraft ───────────┐
            │              │                                        │
            │      SubmitBomReview                                  │
            │       (前置: ≥1 项且每项 part_no 非 DEPRECATED, INV-06)│
            │              │                                        │
            │              v                                        │
            │        [SUBMITTED]                                    │
            │              │                                        │
            │     ┌────────┴───────────────┐                        │
            │     v                         v                        │
            │  ActivateBom               RejectBomReview             │
            │  (前置: 引用校验通过,        (审核驳回, 回 DRAFT,        │
            │   INV-07/INV-08)            带 rejection_notes)        │
            │     │                         │                        │
            │     │ ActivationRejected       │                        │
            │     │ (生效校验失败, 回 DRAFT)  │                        │
            │     v                         v                        │
            │  [ACTIVATED]              [DRAFT]                       │
            │     │                                                    │
            │     │ DeprecateBom                                        │
            │     │ (新版本生效自动触发 superseded_by≠null              │
            │     │  / 手动整体弃用 superseded_by=null)                 │
            │     v                                                    │
            │  [DEPRECATED]                                            │
            │     │                                                    │
            │     │ ArchiveBom                                         │
            │     v                                                    │
            └─▶ [ARCHIVED] ◀──────────────────────────────────────────┘
                  (终态—之后任何事件均拒收, INV-03)
```

**不变式**：
- `-> DRAFT`（新建）：`create()`，产品存在、同 product 无冲突或显式升级
- `DRAFT -> SUBMITTED`：`submitReview()`，前置 ≥1 项且每项 part_no 非 DEPRECATED（INV-06）
- `SUBMITTED -> ACTIVATED`：`activate()`，前置引用校验通过（INV-07/INV-08）；同 `(product_id, bom_type)` 唯一 ACTIVE（BIZ-02，跨实例）
- `SUBMITTED -> DRAFT`：`rejectReview()`/`rejectActivation()`/`rejectSubmission()`
- `ACTIVATED -> DEPRECATED`：`deprecate()`，新版本生效自动触发（`superseded_by≠null`）或手动整体弃用（`superseded_by=null`）
- `DEPRECATED -> ARCHIVED`：`archive()`
- `DRAFT -> ARCHIVED`：`abandonDraft()`
- `ARCHIVED` 之后任何事件均拒收（终态 INV-03）

## 3. 领域服务

领域服务封装**跨聚合**的业务逻辑或**不自然归属**单一聚合根的操作。

### 3.1 BomValidationService（BOM 版本校验服务）

**职责**：编排 BOM 引用完整性校验——提交审核时预校验（INV-06）、生效时引用校验（INV-07/INV-08）。校验失败拒绝 `SubmitBomReview`/`ActivateBom`。

```yaml
BomValidationService:
  方法:
    precheckOnSubmit(bom_version_id):
      # 提交审核时预校验（INV-06），同步查本上下文
      # 1. BomItem 数 ≥ 1？
      # 2. 每项 part_no 非 DEPRECATED？
      # 3. 每项 qty_per_unit > 0？
      # 4. BomSubstituteBinding 引用的 SubstituteRule 存在且有效？
      # 失败 -> Bom.rejectSubmission(failed_checks[]) -> BomReviewSubmissionRejected（回 DRAFT）

    validateOnActivate(bom_version_id):
      # 生效时引用校验（INV-07/INV-08），同步查本上下文
      # 1. 所有 Material 非 DEPRECATED？（INV-07）
      # 2. 所有 BomSubstituteBinding 引用的 SubstituteRule 存在且有效？（INV-08）
      # 失败 -> Bom.rejectActivation(failed_refs[]) -> ActivationRejected（回 DRAFT）
```

> **为什么不放在聚合根内**：引用校验需查询本上下文其它 `Material`/`SubstituteRule` 实例——单条 `Bom` 聚合无权查询其它聚合实例。校验是跨聚合编排，归本服务。与工艺管理上下文 `RouteValidationService` 同构（差异：本上下文审核 BOM 明细引用，工艺管理审核步骤绑定引用）。

---

### 3.2 BomActivationService（BOM 版本生效服务）

**职责**：编排 BOM 版本生效——校验通过后激活版本、同事务弃用同 product 旧版本（BIZ-02 跨实例）、通过事务发件箱发布 `BomActivated` + `BomDeprecated`（INV-CX-02）。

```yaml
BomActivationService:
  方法:
    activate(bom_version_id, activated_by):
      # 1. 委托 BomValidationService.validateOnActivate（INV-07/INV-08）
      #    失败 -> rejectActivation -> ActivationRejected（回 DRAFT）
      # 2. 加载 Bom -> activate(activated_by) -> BomActivated（-> ACTIVATED）
      # 3. 跨实例唯一 ACTIVE 校验（BIZ-02）：
      #    查读模型同 (product_id, bom_type) 的当前 ACTIVATED 版本
      #    + 数据库唯一索引 (product_id, bom_type, status=ACTIVATED)
      # 4. 若存在旧 ACTIVATED 版本 -> 同事务 deprecate(superseded_by=新版本) -> BomDeprecated
      # 5. 事务发件箱（INV-CX-02）：BomActivated + BomDeprecated 与状态变更同事务 outbox
      # 6. 发布到 material.bom.lifecycle
      #    - 在制品追踪上下文订阅 BomActivated -> 重算 KitStatus
      #    - 过点执行上下文订阅 BomActivated -> 刷新物料防错缓存
```

> **为什么不放在聚合根内**：唯一 ACTIVE 版本是跨实例不变式（BIZ-02），单条 `Bom` 无权查询同 product 其它版本实例；自动弃用旧版本是跨聚合编排；事务发件箱发布是跨服务集成。归本服务 + 读模型查询 + 唯一索引共同保证。

> 🔴 **热点：BOM 生效发布的事务发件箱**（事件风暴 §3，INV-CX-02）——`BomActivated` 的发布与 Bom 状态变更（SUBMITTED->ACTIVATED）+ 旧版本 Deprecate 在同一数据库事务内通过 outbox 保证至少一次投递，消费端幂等处理。与工艺管理上下文 `ProcessRouteActivated`、质量上下文 `QualityGateRuleActivated` 同理（跨上下文统一编号）。

### 3.3 InventoryConsumptionService（物料消耗扣减服务）

**职责**：消费过点执行上下文 `CheckpointReleased`，按 BOM 的 `consumption_rule` 计算扣减量，扣减 `Inventory`（最终一致，非过点主事务）。

```yaml
InventoryConsumptionService:
  方法:
    onCheckpointReleased(sn, work_order_id, route_version, product_id, station_id, source_event_id):
      # 来源：过点执行上下文 mes.checkpoint.lifecycle CheckpointReleased
      # 1. 幂等去重：(sn, work_order_id, source_event_id) 去重表（BIZ-04）
      # 2. 查询该 product_id 的 ACTIVE Bom + 各 BomItem 的 consumption_rule
      # 3. 计算 BOM 各项的扣减量（per_unit / per_panel / per_batch / proportional）
      #    - per_panel: 按 work_order_id 拼板配置聚合多个 SN 后按板扣减（🔴 §2.4.2）
      # 4. 判断扣减路径：
      #    - 该 work_order_id 已预占 -> consume(from_locked=true)，扣减 locked_qty
      #    - 未预占（紧急开工未走派工）-> consume(from_locked=false)，扣减 available_qty
      # 5. 加载 Inventory -> consume(...) -> MaterialConsumed + InventoryChanged
      # 6. 超扣则 available_qty 为负并发布告警（INV-13）
      # 7. 发布到 material.inventory.changed（供在制品追踪齐套重算, BIZ-03）
```

> **为什么不放在聚合根内**：物料消耗需查询 `Bom` 聚合（按 product_id 找 ACTIVE BOM）+ 跨实例判断预占状态（查 `InventoryReservation`）+ 按 `consumption_rule` 计算扣减量——跨 `Inventory` + `Bom` + `InventoryReservation` 三聚合。幂等去重（BIZ-04）是跨实例不变式，由本服务 + 去重表保证。

> **物料消耗最终一致语义**（领域总览 §5.3）：物料扣减**不在过点主事务内**，由本服务消费 `CheckpointReleased` 异步扣减，存在秒级延迟。过点放行不阻塞等待扣减完成——过点执行上下文的物料防错校验读的是"扣减前的库存快照"（可能略滞后），但保证过点主事务不被跨服务阻塞。

> 🔴 **热点：物料消耗的扣减时点**（事件风暴 §9）——建议立场已固化：过点放行后扣减库存；若该工单已齐套预占，扣减 `locked_qty`（§1.6）；若未预占（紧急开工），扣减 `available_qty`。两种路径在本服务内统一处理。

### 3.4 InventoryReservationService（齐套预占服务）

**职责**：消费排产/工单上下文派工/开工事件，按 BOM 计算所需物料，齐套预占 `InventoryReservation`（锁定 `locked_qty`）；消费工单取消事件释放预占。

```yaml
InventoryReservationService:
  方法:
    onWorkOrderDispatched(work_order_id, product_id, planned_qty, line_id, source_event_id):
      # 来源：排产/工单上下文 工单派工/开工事件
      # 1. 幂等去重：(work_order_id, source_event_id) 去重表（BIZ-05）
      # 2. 查询 product_id 的 ACTIVE Bom + 各项 available_qty（按 location=该产线线边仓）
      # 3. 计算 planned_qty 套 BOM 所需物料
      # 4. 齐套判定：
      #    - 全部齐套 -> 创建 InventoryReservation（按 location 锁定）+ Inventory.lock -> KitReserved
      #      发布到 material.kit.reserved（供在制品追踪齐套重算, BIZ-03）
      #    - 部分缺料 -> KitReservationFailed（missing_items[]）
      #      发布到 material.kit.reservation-failed（排产/工单上下文订阅，决定延迟开工或部分开工）
      # 5. 同 (work_order_id, part_no, location) 预占不重复创建（BIZ-05，跨实例 + 唯一索引）

    onWorkOrderCancelled(work_order_id, source_event_id):
      # 来源：排产/工单上下文 工单取消事件
      # 1. 幂等去重：(work_order_id, source_event_id) 去重表
      # 2. 加载该 work_order_id 所有 RESERVED 的 InventoryReservation
      # 3. 逐个 release(reason=CANCELLED) -> KitReleased
      #    Inventory.locked_qty 递减
      # 4. 发布到 material.kit.released（供在制品追踪齐套重算, BIZ-03）

    onConsumptionRelease(work_order_id, part_no, location):
      # 内部触发：过点消耗已扣减 locked_qty（InventoryConsumptionService）
      # -> release(reason=CONSUMED) -> KitReleased
```

> **为什么不放在聚合根内**：齐套预占需查询 `Bom` 聚合（按 product_id 找 ACTIVE BOM）+ 跨实例判断库存齐套（查多个 `Inventory`）+ 跨实例去重（同 work_order 不重复预占 BIZ-05）——跨 `InventoryReservation` + `Inventory` + `Bom` 三聚合。归本服务 + 读模型查询 + 唯一索引保证。

### 3.5 InventoryProjectionService（库存变更发布服务）

**职责**：库存入库/消耗/预占/释放后，重算可用库存并幂等发布 `InventoryChanged`（BIZ-03）。

```yaml
InventoryProjectionService:
  方法:
    publishInventoryChange(part_no, location, delta, source_event_id):
      # 1. 幂等去重：source_event_id 事件去重表（BIZ-03）
      # 2. 重算 available_qty / locked_qty
      # 3. 新旧状态比较：无变化则不发布（避免无意义事件）
      # 4. 发布 InventoryChanged(part_no, location, available_qty, locked_qty, delta, source_event_id)
      # 5. 发布到 material.inventory.changed（供在制品追踪齐套重算）
```

> **为什么不放在聚合根内**：库存变更发布需跨实例去重（source_event_id 去重表）+ 新旧状态比较（查读模型）——单条 `Inventory` 聚合无权查询去重表或全局状态。归本服务 + 去重表保证 BIZ-03。

### 3.6 MaterialChangeService（换料事件服务）

**职责**：登记换料动作（料盘换料/替代料启用/ECN 换料），发布 `MaterialChanged` 供首件处理上下文触发首件。

```yaml
MaterialChangeService:
  方法:
    registerMaterialChange(work_order_id, line_id, part_no, change_type, old_part_no?, new_part_no?, substitute_rule_id?, changed_by):
      # 1. 加载 Material -> registerMaterialChange(...) -> MaterialChanged
      # 2. 发布到 material.changed（供首件处理上下文触发首件, 首件处理 §2.1）
      # 3. 作用域：工单级（work_order_id × line_id × part_no）
```

> 🔴 **热点：换料的检测方式**（事件风暴 §2.5）——建议立场已固化：**两者皆可**——操作员手工登记走本服务命令；上料防错系统检测到料盘切换/替代料启用时通过 REST/事件通知本服务发布 `MaterialChanged`。

## 4. 应用服务

应用服务是**外部调用入口**，负责：接收请求 / 事务边界 / 调用领域服务编排 / 发布集成事件。本上下文是配置型主数据 + 库存事实源混合上下文，与在制品追踪/过点执行/首件处理上下文的协作经**异步事件解耦** + **降级查询**，物料消耗经**最终一致**（非过点主事务，领域总览 §5.3）。

### 4.1 MaterialCommandAppService（物料命令应用服务）

**职责**：处理物料主数据/产品/BOM/供应商/替代料规则/换料的写操作命令（REST/物料管理终端入口，发命令者：物控工程师/BOM 工程师/BOM 主管/采购/线边操作员）。

```yaml
MaterialCommandAppService:
  方法:
    # ─── 物料主数据与产品 ───
    registerMaterial(cmd):            # -> Material.register
    updateMaterial(cmd):              # -> Material.update -> FlagAffectedDrafts
    deprecateMaterial(cmd):           # -> Material.deprecate -> FlagAffectedDrafts
    registerProduct(cmd):             # -> Product.register
    updateProduct(cmd):               # -> Product.update
    deprecateProduct(cmd):            # -> Product.deprecate

    # ─── 供应商 ───
    registerSupplier(cmd):            # -> Supplier.register
    updateSupplier(cmd):              # -> Supplier.update
    deprecateSupplier(cmd):           # -> Supplier.deprecate

    # ─── BOM 版本 ───
    createBom(cmd):                   # -> Bom.create（产品存在性校验）
    addBomItem(bom_version_id, part_no, qty_per_unit, consumption_rule, reference_designators[]):
                                      # -> Bom.addBomItem（前置 DRAFT INV-04）
    bindSubstitute(bom_version_id, bom_item_key, substitute_rule_id):
                                      # -> Bom.bindSubstitute（前置 DRAFT；rule 存在性校验 INV-08）
    submitBomReview(bom_version_id, submitted_by):
                                      # -> Bom.submitReview -> BomValidationService.precheckOnSubmit（INV-06）
    activateBom(bom_version_id, activated_by):
                                      # -> BomActivationService.activate（同事务校验 + 激活 + 弃用旧版本 + outbox）
    rejectBomReview(bom_version_id, rejection_notes, rejected_by):
                                      # -> Bom.rejectReview（回 DRAFT）
    deprecateBom(bom_version_id, reason, deprecated_by):
```

| 用例 | 事务边界 | 调用领域对象 | 产出事件 | 幂等策略 |
|------|----------|--------------|----------|----------|
| 登记/更新/弃用物料 | 单聚合事务 | `Material.register`/`update`/`deprecate` | `MaterialRegistered`/`Updated`/`Deprecated` | `commandId`；`part_no` 唯一（INV-01） |
| 建档/更新/弃用产品 | 单聚合事务 | `Product.*` | `ProductRegistered`/`Updated`/`Deprecated` | `commandId` |
| 建档/更新/弃用供应商 | 单聚合事务 | `Supplier.*` | `SupplierRegistered`/`Updated`/`Deprecated` | `commandId` |
| 创建/添加项/绑定 BOM | 单聚合事务 | `Bom.create`/`addBomItem`/`bindSubstitute` | `BomVersionCreated`/`BomItemAdded`/`SubstituteBound` | `commandId`；前置 DRAFT（INV-04） |

| 审核驳回/弃用/归档 BOM | 单聚合事务 | `Bom.rejectReview`/`deprecate`/`archive` | `BomReviewRejected`/`BomDeprecated`/`BomVersionArchived` | `commandId`；终态拒收（INV-03） |
| 定义/激活/失效替代料规则 | 单聚合事务 | `SubstituteRule.*` | `SubstituteRuleDefined`/`Activated`/`Deactivated` | `commandId` |
| 入库 | 单聚合事务 | `Inventory.receive` + `InventoryProjectionService` | `InventoryReceived` + `InventoryChanged` | `commandId`；`source_event_id`（BIZ-03） |
| 换料登记 | 单聚合事务 | `MaterialChangeService.registerMaterialChange` | `MaterialChanged` | `commandId` |

### 4.2 MaterialEventConsumeAppService（事件消费应用服务）

**职责**：订阅上下文外事件，翻译为本上下文命令，委托领域服务处理（事件风暴 §2.6 消费策略）。本上下文以发布为主、消费为辅，消费的上下文外事件主要是过点放行（驱动消耗）与排产派工/取消（驱动预占/释放）。

```yaml
MaterialEventConsumeAppService:
  订阅主题与处理:
    # 过点执行上下文（主题前缀 mes.*）
    mes.checkpoint.lifecycle (CheckpointReleased):
      -> InventoryConsumptionService.onCheckpointReleased
      # 按 BOM consumption_rule 扣减库存（最终一致, BIZ-04）
      # 幂等：(sn, work_order_id, source_event_id) 去重表

    # 排产/工单上下文（🔴 前缀待对齐）
    工单派工/开工事件:
      -> InventoryReservationService.onWorkOrderDispatched
      # 齐套预占（BIZ-05）
      # 幂等：(work_order_id, source_event_id) 去重
    工单取消事件:
      -> InventoryReservationService.onWorkOrderCancelled
      # 释放预占（reason=CANCELLED）
      # 幂等：(work_order_id, source_event_id) 去重

    # 返工上下文（主题前缀 brework.*）
    brework.order.scrapped (BatchReworkOrderScrapped):
      -> RecoverScrappedMaterial（报废物料回收登记, 可选, 🔴 §2.6）
      # 幂等：(rework_order_id, source_event_id) 去重
```

> **降级查询不算"消费事件"**：工艺管理上下文设计 BOM 步骤绑定时 REST 查询本上下文产品/BOM 存在性（设计时同步校验）；过点执行上下文过点时读 BOM/替代料读模型（本地缓存或降级查询本上下文）。这些同步查询不引入分布式事务（领域总览 §5.3）。

> **上下文外事件只消费不重发**（INV-CX-03）：本上下文将订阅事件包装为本上下文语义事件后发布，下游凭主题前缀区分来源。

> **主题命名约定**：本域**对外发布**使用 `material.*` 前缀。本域**订阅**使用各发布域实际前缀（`mes.*`/`brework.*`/排产工单前缀待对齐），不重写。

## 6. 不变规则（Invariants）

不变规则是领域模型中**必须始终为真**的业务约束，无论经过何种操作序列。按**一致性边界**分为三段，**分别编号、不可混列**（编号在此首次诞生；事件风暴侧以无编号"已识别约束"清单对应，见 [事件风暴 - 物料上下文](../事件风暴/物料上下文.md#已识别约束)）：

- **聚合不变式（`INV-XX`）**：落在单一聚合的一致性边界内，事务内强一致、始终为真，由聚合根前置条件 / 状态机 / 规约守护，**按所属聚合根分子节归位**。
- **业务不变式（`BIZ-XX`）**：本上下文内跨聚合 / 跨实例，一致性边界与任意单事务无法重合，最终一致，由领域服务 + 唯一索引 / 事件去重表 / Saga 守护，**禁止挂在聚合根上**。
- **跨上下文不变式（`INV-CX`）**：跨限界上下文，最终一致，由事件订阅 + ACL + 跨服务协调守护（同服务部署时可走本地事务强一致，见各条说明）。

### 6.1 聚合不变式（Aggregate Invariants）

按所属聚合根分子节归位。

#### 6.1.1 Material（物料主数据）

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-01 | `MaterialCategory` 一经确定不可变更；DEPRECATED 后新 BOM 草稿不可引用、已生效 BOM 不受影响（见 INV-04）、不再允许新入库 | `Material.register` 前置 + `category` 不可变；DEPRECATED 限制新草稿，不回写已生效 BOM（`part_no` 全局唯一见 BIZ-01） |

#### 6.1.2 Bom（产品 BOM·版本化）

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-03 | `ARCHIVED` 为终态，之后任何事件均拒收 | `BomVersionState` 状态机；允许从 DEPRECATED / DRAFT 转入 |
| INV-04 | BOM 生效后 BomItem 与替代料绑定不可变（保证过点记录 BOM 快照完整性） | `Bom` 在 ACTIVATED/DEPRECATED/ARCHIVED 态拒收任何 `addBomItem`/`bindSubstitute` 命令；保证过点执行上下文 `CheckpointRecord` 的 BOM 快照可永久回溯 |
| INV-06 | 提交审核前置：至少 1 项 BomItem 且每项 part_no 非 DEPRECATED | `Bom.submitReview` 前置 + `BomValidationService.precheckOnSubmit` |
| INV-07 | 生效前置：所有 Material 非 DEPRECATED | `BomValidationService.validateOnActivate`（查本上下文） |

#### 6.1.3 Inventory（库存事实）

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-13 | `available_qty + locked_qty ≤ 物理库存总量`（允许 `available_qty` 为负但告警） | `Inventory.consume` 超扣则记负并告警，不禁止扣减（避免逼出跨服务事务回滚过点，🔴 §2.4.2 热点立场） |

## 9. 领域服务与应用服务的关系

```
┌──────────────────────────────────────────────────────────────────────┐
│                           外部调用入口                                  │

│                                                                      │
│  消息消费 ───▶ MaterialEventConsumeAppService (应用服务)              │
│                 └─ 翻译 mes.*/brework.* 事件 -> 委托领域服务            │
│                   （包装为本上下文语义事件后发布，INV-CX-03）              │
│                                                                      │
│  查询请求 ───▶ MaterialQueryAppService (应用服务，读模型)             │
│                 └─ 直接查询读模型投影（含过点降级查询 ≤500ms）         │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           领域服务层                                    │
│  BomValidationService │ BomActivationService │ InventoryConsumptionService│
│  InventoryReservationService │ InventoryProjectionService │ MaterialChangeService│
│  └─ 封装跨聚合规则，加载聚合，调用聚合行为，写仓储，返回领域事件           │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           聚合根（领域层）                              │
│  Material / Product / Bom / Supplier / SubstituteRule                │
│  Inventory / InventoryReservation                                    │
│  └─ 表达业务状态、行为、不变式、领域事件；不依赖 Spring/MQ/HTTP          │
└──────────────────────────────────────────────────────────────────────┘
```

**原则**：
- 应用服务不包含业务逻辑，只做编排和事务边界（CLAUDE.md 分层）
- 领域服务封装跨聚合的业务规则，每个领域服务必答"为什么不放在聚合根内"
- 聚合根内的业务逻辑由聚合根自身保证，行为是业务动词方法（非 `update/save` 流水账）
- 不变式由聚合根 + 领域服务 + 唯一索引/事件去重表共同守护
- 物料消耗最终一致 + 降级查询不引入分布式事务（INV-CX-04）；配置型主数据生效经 outbox（INV-CX-02）
