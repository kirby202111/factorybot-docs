## 0. 建模总览

本域是生产执行服务下的**工单生命周期子域**，是 PCBA + 整机组装混合型车间所有"正常生产工单"的身份与状态权威源。核心职责是管理**SAP 工单接收与建档、计划员审核与 MES 工单流水号生成、产品流水号发放、BOM/工艺路线版本绑定、工单下达、状态流转（下达/进行中/暂停/完工/关闭/取消）、工单变更、工单齐套状态判定、完工判定与结案**——即"**工单怎么下、状态怎么流转、物料齐不齐套、何时完工结案**"；**不负责**工单创建源头（全部来自 SAP，MES 不允许创建工单）、不负责工单执行进度累计（归在制品执行上下文，本上下文消费其进度事件做完工判定）、不负责工艺路线定义与版本生命周期（归工艺管理上下文，本上下文只读引用路线版本）、不负责 BOM 与物料主数据（归物料上下文，本上下文只读引用 BOM 版本）、不负责批量返工工单（归返工上下文 `BatchReworkOrder`，本上下文的 `WorkOrder` 是其 `source_work_order_id` 的来源）、不负责单件返修任务（归返修上下文）、不负责在制品单件位置投影与流转历史（归在制品执行上下文；工单齐套状态判定归本上下文 `KitStatus`，见下文）、不负责排产（归排产上下文，本上下文消费 `schedule.*` 回写 MES 排产快照；SAP 建议字段与 MES 排产快照并存，互不覆盖 INV-CX-08）。

本上下文与在制品执行上下文是"工单生命周期"与"在制品执行进度"的分工关系，通过事件契约解耦：本上下文发布 `wo.order.*` 事件供在制品执行上下文缓存工单状态做校验；在制品执行上下文发布 `mes.workorder.progress` 供本上下文做完工判定。本上下文与返工上下文单向引用——返工工单引用源工单（`source_work_order_id`），源工单不引用返工工单。SAP 工单接收经本上下文 ACL（端口 `WorkOrderReceptionPort`）按 `source_event_id` 幂等去重。

本上下文亦承担**工单齐套状态判定**：消费物料上下文 `material.*` 事件（BOM 生效、库存变更、替代料生效/失效、齐套预占/释放）重算 `KitStatus`（`kit_ready` + `missing_items[]`，双向可逆 INV-08），发布 `wo.kit.status` 供在制品执行上下文（首次过点齐套防错）与排产上下文（投放/重排决策）消费。`KitStatus` 是**独立聚合根**（工单级判定型），与 `WorkOrder` 生命周期聚合分离--物料事件只加载 `KitStatus` 聚合重算，不拖重 `WorkOrder` 聚合。`wo.order.released` 触发本上下文内部建档 `KitStatus`（下达时 BOM 版本已锁定，齐套判定有了依据）。齐套判定原归属原在制品追踪上下文（已并入在制品执行上下文），2026-07-09 迁入本上下文（见 §变更说明）。

> **聚合边界说明**：事件风暴统一语言中的 `WorkOrderItem` / `WorkOrderBinding` / `WorkOrderClosure` **不是独立聚合根**——`WorkOrderItem` 建模为 `WorkOrder` 的 `item` 属性（值对象，当前单产品，预留多明细扩展），`WorkOrderBinding` 建模为 `WorkOrder` 的 `binding` 属性（值对象，BOM + 工艺路线版本快照），`WorkOrderClosure` 建模为 `WorkOrder` 的 `closure` 属性（值对象，完工判定与结案信息）。`ProductSerialNo` 是独立聚合根——产品流水号有独立身份与生命周期（按 `target_qty` 等量生成、首工序绑定、限定投产数量），由 `ProductSerialNoService` 批量生成。`MesSerialNo` 是 `WorkOrder` 的值对象属性（MES 工单流水号），由 `MesSerialNumberService` 按前缀递增生成。`KitStatus` 是独立聚合根（工单级齐套判定，双向可逆 INV-08）--与 `WorkOrder` 生命周期聚合分离：物料事件只加载 `KitStatus` 重算，不拖重 `WorkOrder`；由 `KitStatusService` 消费 `material.*` 事件重算。这样 3 个聚合根各自守护单一一致性边界，明细/绑定/结案/流水号/齐套判定各归其聚合，避免聚合碎片化；齐套独立成聚合避免物料高频重算冲击工单生命周期聚合。

## 1. 聚合根

### 1.1 WorkOrder（工单）

**一致性边界**：单个工单的身份、产品明细、目标数量、BOM/工艺路线版本绑定、状态生命周期、完工判定与结案。

**职责**：接收 SAP 下发工单并建档；承载计划员审核与 MES 工单流水号生成；绑定 BOM/工艺路线版本快照；管理 CREATED->RELEASED->IN_PROGRESS->(PAUSED)->COMPLETED->CLOSED / CANCELLED 完整状态机；工单变更（数量/计划时间/产线）；完工判定与结案；发布工单生命周期事件供下游消费。

```yaml
WorkOrder:
  # ─── 标识 ───
  work_order_id:     WorkOrderId          # 工单唯一标识（聚合根ID）

  # ─── SAP 来源 ───
  work_order_no:     String               # SAP 工单号（业务可读，来自 SAP）
  source:            WorkOrderSource      # SAP（MES 不允许创建工单）
  source_event_id:   String?              # 来源事件 ID（幂等去重键，BIZ-01）

  # ─── MES 工单流水号 ───
  mes_serial_no:     MesSerialNo?         # MES 工单流水号（计划员审核通过后生成；当前与 SAP 工单一对一，预留一对多扩展）

  # ─── 产品明细 ───
  item:              WorkOrderItem        # 工单明细（当前单产品，预留多明细扩展 INV-15）

  # ─── 目标 ───
  target_qty:        Integer              # 目标数量
  unit:              Unit                 # 单位（PCS / SET）

  # ─── 工单分类 ───
  work_order_type:   WorkOrderType        # 工单类型（来自 SAP 或经 ACL 归一化）
  production_year:   Integer              # 所属年份（用于产品流水号前缀解析）
  material_type:     String               # 生产产品的物料类型（用于产品流水号前缀解析）

  # ─── 版本绑定 ───
  binding:           WorkOrderBinding?    # BOM + 工艺路线版本快照（CREATED 阶段可为空；审核下达时锁定 INV-01）

  # ─── SAP 参考计划信息 ───
  planned_start_at:  DateTime?            # 计划开工时间（SAP 下发，仅参考）
  planned_finish_at: DateTime?            # 计划完工时间（SAP 下发，仅参考）
  production_line_id: String?             # 产线 ID（SAP 下发，仅参考）

  # ─── MES 排产快照（消费 schedule.* 回写，与 SAP 建议并存）───
  mes_schedule:      MesScheduleSnapshot?  # MES 排产快照（排产上下文确认/重排/释放时回写；与 SAP 建议字段并存，互不覆盖 INV-CX-08）

  # ─── 状态 ───
  status:            WorkOrderStatus      # CREATED / RELEASED / IN_PROGRESS / PAUSED / COMPLETED / CLOSED / CANCELLED

  # ─── 结案 ───
  closure:           WorkOrderClosure?    # 完工判定与结案信息（COMPLETED / CLOSED 时填充）

  # ─── 审计 ───
  created_at:        DateTime
  released_at:       DateTime?
  completed_at:      DateTime?
  closed_at:         DateTime?
  cancelled_at:      DateTime?
  cancel_reason:     String?
```

**行为**：
- `receiveFromSap(work_order_no, product_id, target_qty, unit, work_order_type, production_year, material_type, planned_start_at, planned_finish_at, production_line_id, source_event_id)` -> 发出 `SapWorkOrderReceived` + `WorkOrderCreated`（前置：`source_event_id` 幂等去重通过 BIZ-01；-> `CREATED`）
- `reviewAndRelease(bom_binding, route_binding, mes_serial_no, serial_no_prefix, released_by)` -> 发出 `WorkOrderBindingLocked` + `MesSerialNoGenerated` + `WorkOrderReleased`（前置：当前 `CREATED`；`binding` 非空 INV-01；-> `RELEASED`；经 `WorkOrderReleaseService` 编排）
- `start()` -> 发出 `WorkOrderStarted`（前置：当前 `RELEASED`；首次过点 `CheckpointReleased` 自动触发 INV-10；-> `IN_PROGRESS`）
- `pause(pause_reason)` -> 发出 `WorkOrderPaused`（前置：当前 `IN_PROGRESS`；-> `PAUSED`）
- `resume()` -> 发出 `WorkOrderResumed`（前置：当前 `PAUSED`；-> `IN_PROGRESS`）
- `change(changed_fields, change_reason)` -> 发出 `WorkOrderChanged`（前置：当前 `CREATED` 或 `RELEASED`；若包含 `target_qty` 变更且当前 `IN_PROGRESS` 则拒绝 INV-16；若包含 `bom_binding`/`route_binding` 变更且当前 `RELEASED`/`IN_PROGRESS` 则拒绝 INV-07）
- `rejectQuantityChange(requested_target_qty)` -> 发出 `WorkOrderQuantityChangeRejected`（前置：当前 `IN_PROGRESS`；原因 `WorkOrderAlreadyInProgress` INV-16）
- `rejectBindingChange(requested_bom_version, requested_route_version)` -> 发出 `WorkOrderBindingChangeRejected`（前置：当前 `RELEASED` 或 `IN_PROGRESS`；原因 `WorkOrderAlreadyReleasedOrInProgress` INV-07）
- `complete(completed_product_qty)` -> 发出 `WorkOrderCompleted`（前置：当前 `IN_PROGRESS`；`completed_product_qty >= target_qty` INV-CX-01；-> `COMPLETED`）
- `close(closure_reason)` -> 发出 `WorkOrderClosed`（前置：当前 `COMPLETED`；`closure_reason=CompletedProductQtyReachedTarget`；-> `CLOSED`，终态 INV-03）
- `cancel(cancel_reason, authorized_by?, in_progress_sn_disposal?)` -> 发出 `WorkOrderCancelled`（前置：当前 `CREATED`/`RELEASED` 且无在制过点，或当前 `IN_PROGRESS` 且有授权记录与在制 SN 处理方式 INV-CX-02；-> `CANCELLED`，终态 INV-03）
- `applyMesSchedule(line_id, planned_start_at, planned_finish_at, source_event_id)` -> 更新 `mes_schedule` 快照（前置：当前非 `CLOSED`/`CANCELLED` 终态；`source_event_id` 幂等去重；无独立生命周期事件；由消费 `schedule.confirmed`/`schedule.rescheduled` 触发，经 `WorkOrderEventConsumeAppService` 编排 INV-CX-08）
- `clearMesSchedule(source_event_id)` -> 清空 `mes_schedule` 快照（前置：当前非 `CLOSED`/`CANCELLED` 终态；由消费 `schedule.released` 触发 INV-CX-08）

> **编号语义已确认**：`work_order_no` 表示 SAP 工单号，来源于 SAP；`mes_serial_no` 表示该工单在 MES 内部的工单流水号，由计划员审核通过时生成，并作为 `ReviewAndReleaseWorkOrder` 的前置条件。当前阶段一张 SAP 工单对应一个 MES 工单流水号，但模型保留一对多扩展空间（INV-13）。

> **MES 工单流水号规则已确认**：流水号生成依赖产品流水号前缀。前缀由 `ProductSerialPrefixResolver`（领域辅助组件）根据生产产品的 `material_type`、`work_order_type` 与 `production_year` 解析；相同前缀下序号递增增长。流水号一经生成不可回收，取消/作废工单也不复用已发号段；并通过唯一索引保证 `mes_serial_no` 全局唯一（BIZ-03）。

> **已确认：BOM/工艺路线版本在计划员审核下达时锁定**——SAP 工单进入 MES 的 CREATED 阶段不固化版本；计划员执行 `ReviewAndReleaseWorkOrder` 时，实时查询物料上下文与工艺管理上下文，锁定 BOM 版本和工艺路线版本快照，并生成 `WorkOrderBindingLocked`。若版本缺失、未发布或不适用于该产品/产线，则拒绝下达。

> **已确认：IN_PROGRESS 后禁止调整 target_qty**（INV-16）——工单一旦发生首次过点进入 `IN_PROGRESS`，目标数量不再实时调整，完工判定继续使用进入在制时的 `target_qty`。若在制后发生客户取消、数量增补或剩余数量不再生产，应通过取消剩余量、拆分/新建工单或异常流程处理。

> **已确认：在制后禁止变更 BOM/工艺路线版本**（INV-07）——`WorkOrderBinding` 在审核下达时锁定；`RELEASED`/`IN_PROGRESS` 状态下不允许直接变更 BOM 或工艺路线版本。若生产过程中发现产品 BOM 或工艺路线需调整，应由质量/工程变更触发返工流程处理。

> **已确认：完工产品数量达成后自动结案**——`COMPLETED` 不是"最后一道工序刚过点"的瞬时状态，而是产品最后一道工序过点完成且无未关闭质量单、返修单等关联异常后的汇总状态。当 `completed_product_qty >= target_qty` 时，本上下文自动产生 `WorkOrderCompleted` 并紧接着自动产生 `WorkOrderClosed`（INV-11），无需人工结案确认。

> **已确认：不存在超产场景**（BIZ-04）——开工前按 `target_qty` 创建等量产品流水号，工艺路线第一步要求将产品流水号绑定到对应产品；未发放产品流水号的产品无法进入首工序过点。因此工单完工判定仍为 `completed_product_qty >= target_qty`，但正常执行中 `completed_product_qty` 不应超过 `target_qty`。

> 🔴 **热点：工单下达与首件触发的时序**——`WorkOrderReleased` 发布后，首件处理上下文触发首件标识判定。首件未放行前，在制品执行上下文是否拦截批量过点？建议：**首件门禁由在制品执行上下文执行**（消费 `fai.article.blocked` 拦截，消费 `fai.article.released` 放行），本上下文只发布 `WorkOrderReleased` 通知首件处理上下文触发判定，不直接参与门禁。待与首件处理上下文确认触发契约。

### 1.2 ProductSerialNo（产品流水号）

**一致性边界**：单个产品流水号的身份、前缀、序号、绑定状态。

**职责**：开工前按 `target_qty` 等量生成产品流水号（BIZ-04）；首工序绑定时记录绑定信息；限定投产数量，杜绝超产。

```yaml
ProductSerialNo:
  # ─── 标识 ───
  serial_no_id:      ProductSerialNoId    # 流水号唯一标识（聚合根ID）
  serial_no:         String               # 产品流水号（prefix + sequence_no）

  # ─── 关联 ───
  work_order_id:     WorkOrderId          # 所属工单
  mes_serial_no:     MesSerialNo          # 所属 MES 工单流水号

  # ─── 前缀与序号 ───
  prefix:            ProductSerialPrefix  # 流水号前缀（由 material_type + work_order_type + production_year 解析）
  sequence_no:       Integer              # 前缀下序号

  # ─── 状态 ───
  state:             ProductSerialNoState # GENERATED / BOUND / SCRAPPED
  product_id:        String?              # 绑定的产品 ID（BOUND 时填充）
  bound_at:          DateTime?            # 绑定时间
  bound_checkpoint:  String?              # 绑定过点记录 ID（首工序过点记录）

  # ─── 审计 ───
  generated_at:      DateTime
```

**行为**：
- `generateBatch(work_order_id, mes_serial_no, prefix, count)` -> 发出 `ProductSerialNoBatchGenerated`（前置：`count` 等于 `target_qty` BIZ-04；同前缀下序号递增；-> `GENERATED`）
- `bindToProduct(product_id, checkpoint_id)` -> 发出 `ProductSerialNoBound`（前置：当前 `GENERATED`；-> `BOUND`；由在制品执行上下文首工序过点时调用）

> **产品流水号发放边界**：开工前计划员按 `target_qty` 创建等量产品流水号，工艺路线第一步将产品流水号绑定到对应产品。该机制限定可投产数量，因此不存在超产场景（BIZ-04）。`ProductSerialNoBound` 事件由在制品执行上下文在首工序过点时发布，本上下文消费该事件更新流水号状态。

> **已确认：流水号前缀映射表归属**——`material_type + work_order_type + production_year -> serial_no_prefix` 的映射规则由本上下文配置字典维护；`ProductSerialPrefixResolver` 作为本上下文的领域辅助组件读取该配置并解析前缀。物料上下文只提供 `material_type` 等输入枚举/主数据，不承担 MES 工单流水号规则维护职责。

### 1.3 KitStatus（工单齐套状态）

**一致性边界**：单个工单的物料齐套判定状态。

**职责**：消费物料上下文事件重算 `kit_ready` 与 `missing_items[]`；双向可逆（齐套后可因缺料回到 NOT_READY INV-08）；幂等去重（`work_order_id + source_event_id`，无变化不发布 BIZ-08）；`wo.order.released` 触发建档（下达时 BOM 版本已锁定）；发布 `KitStatusChanged` 供在制品执行/排产消费。

```yaml
KitStatus:
  # ─── 标识 ───
  work_order_id:    WorkOrderId         # 工单标识（聚合根ID，与 WorkOrder 同维度但不持有 WorkOrder 聚合）

  # ─── 齐套判定 ───
  kit_ready:        Boolean             # 是否齐套（true ⇔ missing_items 为空 INV-08）
  missing_items[]:  List<KitItem>       # 缺料明细（kit_ready=true 时为空）

  # ─── 审计 ───
  last_source_event_id: String          # 最后一条来源事件ID（幂等去重键 BIZ-08）
  last_changed_at:  DateTime            # 最后齐套状态变更时间
  initialized_at:   DateTime            # 建档时间（wo.order.released 时）
```

**行为**：
- `initOnRelease(work_order_id, bom_binding, source_event_id)` -> 发出 `KitStatusChanged`（前置：由 `WorkOrderReleased` 触发；建档 `KitStatus`，按当前已知库存判定初始 `kit_ready`，或置 NOT_READY 待首条物料事件重算；幂等 `work_order_id` 去重仅建档一次）
- `recompute(items[], source_event_id)` -> 发出 `KitStatusChanged`（前置：`source_event_id` 幂等去重 BIZ-08；按 `items[]` 判定 `kit_ready` 与 `missing_items`；新旧状态比较--无变化则不发布 BIZ-08；`kit_ready` 双向可逆 INV-08）

> **判定型聚合的本质**：`KitStatus` 是**可逆**的--与在制品执行上下文 `WipUnit` 的终态不同，`kit_ready` 可从 `true` 回到 `false`（若物料上下文报告缺料/替代料失效）。`KitStatus` 不做 BOM 解析或库存查询--这些是物料上下文的职责，本上下文仅消费其事件判定结果。

> **齐套状态不设独立读模型**：`KitStatus` 聚合本身数据量小（每个工单一条记录），查询直接读聚合即可，无需额外投影。`KitStatusChanged` 事件发布到 `wo.kit.status` 供在制品执行（首次过点齐套防错）/排产（投放/重排决策）消费。

> **建档时机**：`wo.order.released`（计划员审核下达、BOM 版本已锁定）时由 `WorkOrderReleaseService` 委托 `KitStatusService.initOnRelease` 建档--下达时 BOM 已知，齐套判定有了依据。建档后开始消费 `material.*` 事件持续重算。

WorkOrderClosure:

### 2.5 WorkOrderStatus（工单状态）

```yaml
WorkOrderStatus:
  - CREATED      # 已创建（SAP 下发，待计划员审核）
  - RELEASED     # 已下达（审核通过，已生成流水号并锁定版本，允许过点）
  - IN_PROGRESS  # 进行中（首次过点已放行，正在生产）
  - PAUSED       # 已暂停（暂停原因记录，过点拦截 INV-CX-04）
  - COMPLETED    # 已完工（完工产品数量达到 target_qty INV-CX-01）
  - CLOSED       # 已结案（终态，INV-03）
  - CANCELLED    # 已取消（终态，INV-03）
```

**状态机**：

```
[SAP 下发]
     |
     v
[CREATED] ──ReviewAndReleaseWorkOrder──▶ [RELEASED] ──StartWorkOrder──▶ [IN_PROGRESS] ──CompleteWorkOrder──▶ [COMPLETED] ──CloseWorkOrder──▶ [CLOSED]
     │                                                                      │                                     (终态—完工判定通过, INV-CX-01)
     │                                                                      │
     │                                                                      └──PauseWorkOrder──▶ [PAUSED] ──ResumeWorkOrder──▶ [IN_PROGRESS]
     │
     └──CancelWorkOrder──▶ [CANCELLED]
                             (终态—取消, INV-03)

[RELEASED] ──CancelWorkOrder──▶ [CANCELLED]（下达后无在制可取消 INV-CX-02）
[IN_PROGRESS] ──CancelWorkOrder──▶ [CANCELLED]（已有过点在制时需授权并记录在制 SN 处理方式 INV-CX-02）
```

**不变式**：
- `-> CREATED`：`receiveFromSap()`，`source_event_id` 幂等去重（BIZ-01）
- `CREATED -> RELEASED`：`reviewAndRelease()`，前置：`binding` 非空（INV-01）、`mes_serial_no` 已生成（BIZ-03）
- `RELEASED -> IN_PROGRESS`：`start()`，由首次过点 `CheckpointReleased` 自动触发（INV-10）
- `IN_PROGRESS -> PAUSED`：`pause(reason)`，前置 `IN_PROGRESS`
- `PAUSED -> IN_PROGRESS`：`resume()`，前置 `PAUSED`
- `IN_PROGRESS -> COMPLETED`：`complete(completed_product_qty)`，前置 `completed_product_qty >= target_qty`（INV-CX-01）
- `COMPLETED -> CLOSED`：`close(CompletedProductQtyReachedTarget)`，自动结案（INV-11）
- `CREATED/RELEASED -> CANCELLED`：`cancel()`，前置无在制过点（INV-CX-02）
- `IN_PROGRESS -> CANCELLED`：`cancel()`，前置授权记录 + 在制 SN 处理方式（INV-CX-02）
- `CLOSED` / `CANCELLED` 之后任何事件均拒收（终态 INV-03）
- 状态单向流转，仅 `PauseWorkOrder` / `ResumeWorkOrder` 允许回退（INV-06）

## 3. 领域服务

领域服务封装**跨聚合**的业务逻辑或**不自然归属**单一聚合根的操作。

### 3.1 WorkOrderReceptionService（工单接收服务）

**职责**：消费 SAP 下发工单消息，经 ACL 归一化后按 `source_event_id` 幂等去重，创建 `CREATED` 状态 `WorkOrder`。

```yaml
WorkOrderReceptionService:
  方法:
    receiveSapWorkOrder(work_order_no, product_id, target_qty, unit, work_order_type,
                        production_year, material_type, planned_start_at, planned_finish_at,
                        production_line_id, source_event_id):
      # 来源：本上下文 SAP 工单接收适配层（ACL，端口：WorkOrderReceptionPort）
      # 1. 幂等去重：source_event_id 去重表（BIZ-01）
      # 2. 字段归一化：work_order_type 归一化、material_type 枚举校验
      # 3. 创建 WorkOrder -> receiveFromSap(...) -> SapWorkOrderReceived + WorkOrderCreated
      # 4. -> CREATED，等待计划员审核
```

> **为什么不放在聚合根内**：SAP 接收需跨实例查询 `source_event_id` 去重表（BIZ-01），单条 `WorkOrder` 聚合无权查询其它实例。字段归一化（ACL 职责）与幂等去重是跨实例不变式，由本服务 + 事件去重表保证。

> **已确认：SAP 通过消息推送工单下发**——SAP / 中间件主动推送工单下发消息，本上下文的 SAP 工单接收适配层（ACL，端口：`WorkOrderReceptionPort`）负责消费消息、字段归一化与 `source_event_id` 幂等去重，然后触发 `ReceiveSapWorkOrder` 建档。不采用 MES 定时拉取或人工导入作为当前主链。

---

### 3.2 WorkOrderReleaseService（工单下达服务）

**职责**：编排计划员审核下达流程——校验产线/计划时间、解析产品流水号前缀、生成 MES 工单流水号、查询并锁定 BOM/工艺路线版本、下达工单。

```yaml
WorkOrderReleaseService:
  方法:
    reviewAndRelease(work_order_id, released_by):
      # 前置：WorkOrder 当前 CREATED
      # 1. 基础校验：production_line_id 存在、产线支持该产品/工艺路线、计划时间格式与先后关系合法
      # 2. 解析产品流水号前缀：ProductSerialPrefixResolver.resolve(material_type, work_order_type, production_year)
      # 3. 生成 MES 工单流水号：委托 MesSerialNumberService.generate(prefix) -> MesSerialNo
      # 4. 查询并锁定 BOM 版本：REST 查询物料上下文（bom_id + 当前生效 bom_version）
      # 5. 查询并锁定工艺路线版本：REST 查询工艺管理上下文（route_id + 当前生效 route_version）
      # 6. 若版本缺失/未发布/不适用 -> 拒绝下达
      # 7. WorkOrder.reviewAndRelease(bom_binding, route_binding, mes_serial_no, serial_no_prefix, released_by)
      #    -> WorkOrderBindingLocked + MesSerialNoGenerated + WorkOrderReleased
      # 8. 同事务 Outbox 发布到 wo.order.released
      # 9. 按 target_qty 等量生成产品流水号：委托 ProductSerialNoService.generateBatch(work_order_id, mes_serial_no, prefix, target_qty)
      # 10. 建档 KitStatus：委托 KitStatusService.initOnRelease(work_order_id, bom_binding, source_event_id)
      #     （下达时 BOM 版本已锁定，齐套判定有了依据；建档后消费 material.* 持续重算）
```

> **为什么不放在聚合根内**：审核下达需跨上下文 REST 查询 BOM/工艺路线版本（物料上下文 + 工艺管理上下文）、跨聚合生成 `MesSerialNo`（`MesSerialNumberService`）、跨聚合批量生成 `ProductSerialNo`（`ProductSerialNoService`）、基础校验（产线存在性/产品适用性）需查询外部——单条 `WorkOrder` 聚合无权跨上下文查询或推进其它聚合。版本锁定快照 + 流水号生成 + 产品流水号批量生成是跨聚合/跨上下文编排，归本服务。

> **已确认：版本查询与锁定发生在计划员审核下达时**——`ReviewAndReleaseWorkOrder` 实时查询 BOM/工艺路线版本并锁定快照；CREATED 阶段不锁定版本。工单审核下达是低频操作（相比过点毫秒级），建议默认不缓存，避免缓存漂移；若性能压力，可考虑短 TTL 缓存。

> **已确认：不响应 BOM/工艺路线版本主动通知来切换在制工单**——本上下文只在 `ReviewAndReleaseWorkOrder` 时查询并锁定当前生效版本；CREATED 工单尚未锁定版本，已 `RELEASED`/`IN_PROGRESS` 工单的绑定不受新版本发布影响且不允许直接切换（INV-07）。若需因 ECN/质量问题处理已在制产品，应由返工流程承接。

---

### 3.3 WorkOrderCompletionService（工单完工判定与结案服务）

**职责**：消费在制品执行上下文 `WorkOrderProgressAccrued`，判定完工产品数量是否达到目标，达到后自动完工并结案。

```yaml
WorkOrderCompletionService:
  方法:
    onWorkOrderProgressAccrued(work_order_id, completed_product_qty, wip_qty, bad_qty, repair_pending_qty, accrued_at):
      # 来源：在制品执行上下文 mes.workorder.progress WorkOrderProgressAccrued
      # 1. 幂等去重：(work_order_id, accrued_at) 去重表（BIZ-02）
      # 2. 更新 WorkOrderProgressProjection 读模型
      # 3. 加载 WorkOrder，若 status ≠ IN_PROGRESS -> 忽略
      # 4. 比较 completed_product_qty >= target_qty ?
      #    否 -> 保持 IN_PROGRESS，等待后续进度汇总
      #    是 -> WorkOrder.complete(completed_product_qty) -> WorkOrderCompleted
      #         -> WorkOrder.close(CompletedProductQtyReachedTarget) -> WorkOrderClosed
      # 5. Outbox 发布到 wo.order.completed / wo.order.closed
```

> **为什么不放在聚合根内**：完工判定需消费外部事件（`WorkOrderProgressAccrued`）、跨实例幂等去重（`work_order_id + accrued_at`）、更新读模型投影——单条 `WorkOrder` 聚合无权消费外部事件或查询去重表。完工判定逻辑（`completed_product_qty >= target_qty`）本身简单，但编排消费+去重+投影+自动结案是跨聚合/跨上下文职责，归本服务。

> **已确认：进度事件在完工状态变化时发布**——`WorkOrderProgressAccrued` 不要求每次普通过点都发布；仅当产品完工汇总状态发生变化时发布（最后一道工序完成、质量单关闭、返修单关闭等导致 `completed_product_qty`/`wip_qty`/`bad_qty`/`repair_pending_qty` 变化）。本上下文以 `(work_order_id, accrued_at)` 幂等去重。

### 3.4 MesSerialNumberService（MES 工单流水号生成服务）

**职责**：按产品流水号前缀解析结果，在同一前缀下递增生成全局唯一 `MesSerialNo`。

```yaml
MesSerialNumberService:
  方法:
    generate(prefix):
      # 1. 查询当前前缀下最大 sequence_no（读模型或数据库）
      # 2. sequence_no = max_sequence_no + 1
      # 3. 构造 MesSerialNo(serial_no_prefix=prefix, sequence_no, value=prefix+sequence_no)
      # 4. 唯一索引 (serial_no_prefix, sequence_no) 保证并发安全（BIZ-03）
      # 5. 已生成流水号不可回收，取消/作废工单也不复用已发号段
```

> **为什么不放在聚合根内**：流水号生成需跨实例查询同前缀下最大序号（跨实例查询），`WorkOrder` 聚合无权查询其它工单实例。并发安全由唯一索引 `(serial_no_prefix, sequence_no)` 保证，单聚合无法保证跨实例唯一性（BIZ-03）。

> **已确认：流水号前缀映射表归属**——`material_type + work_order_type + production_year -> serial_no_prefix` 的映射规则由本上下文配置字典维护；`ProductSerialPrefixResolver` 作为本上下文的领域辅助组件读取该配置并解析前缀。

### 3.5 ProductSerialNoService（产品流水号服务）

**职责**：按 `target_qty` 等量批量生成产品流水号，保证数量一致性与前缀下序号递增。

```yaml
ProductSerialNoService:
  方法:
    generateBatch(work_order_id, mes_serial_no, prefix, count):
      # 前置：count == WorkOrder.target_qty（BIZ-04）
      # 1. 查询当前前缀下最大 sequence_no
      # 2. 批量生成 count 个 ProductSerialNo -> ProductSerialNoBatchGenerated
      # 3. 唯一索引 serial_no 保证全局唯一
      # 4. 同事务写入（与 WorkOrder 下达同事务）
```

> **为什么不放在聚合根内**：批量生成需跨实例查询同前缀下最大序号（跨实例），`ProductSerialNo` 单聚合无权查询其它实例。数量一致性校验（`count == target_qty`）需跨聚合读取 `WorkOrder.target_qty`。归本服务 + 唯一索引保证。

### 3.6 KitStatusService（齐套状态服务）

**职责**：消费物料上下文 `material.*` 事件重算 `KitStatus`；建档（`wo.order.released` 时 `initOnRelease`）；幂等去重（`work_order_id + source_event_id` 去重表 BIZ-08）；新旧状态比较（无变化不发布 BIZ-08）；处理双向可逆（INV-08）。

```yaml
KitStatusService:
  方法:
    initOnRelease(work_order_id, bom_binding, source_event_id):
      # 触发：WorkOrderReleased（经 WorkOrderReleaseService 第 10 步委托，同事务）
      # 1. 幂等：work_order_id 去重（建档仅一次）
      # 2. 创建 KitStatus(work_order_id)；按当前已知库存判定初始 kit_ready，或置 NOT_READY 待首条物料事件重算
      # 3. KitStatus.initOnRelease(...) -> KitStatusChanged（发布到 wo.kit.status）

    onMaterialEvent(work_order_id, items[], source_event_id):
      # 来源：物料上下文 material.* 物料齐套相关事件
      #   - material.bom.lifecycle (BomActivated / BomDeprecated)
      #   - material.inventory.changed (InventoryChanged)
      #   - material.substitute.lifecycle (SubstituteRuleActivated / Deactivated)
      #   - material.kit.reserved (KitReserved)
      #   - material.kit.released (KitReleased)
      # 1. 幂等去重：work_order_id + source_event_id 去重表（BIZ-08）
      # 2. 加载或新建 KitStatus(work_order_id)（若未建档则建档后重算）
      # 3. recompute(items[], source_event_id)：
      #    a. 按 items[] 判定 kit_ready（全部齐套 -> true，否则 -> false）
      #    b. 计算 missing_items[]（shortage_qty > 0 的项）
      #    c. 比较新旧状态：
      #       - 无变化 -> 不发布，不更新（幂等 BIZ-08）
      #       - 有变化 -> 更新聚合 -> KitStatusChanged（发布到 wo.kit.status）
      # 4. KitStatus 双向可逆（INV-08）：kit_ready 可从 true -> false（缺料/替代料失效）
```

> **为什么不放在聚合根内**：`KitStatusService` 需消费物料上下文事件（跨上下文）、按 `work_order_id + source_event_id` 做幂等去重--单条 `KitStatus` 聚合无权查询去重表或自我驱动事件消费。齐套重算需综合 BOM + 库存 + 替代料（物料上下文职责），本服务编排"接收物料事件 -> 判定 -> 发布"的完整链路，聚合根只负责 `recompute()` 的内部判定逻辑。建档由 `WorkOrderReleaseService` 同事务委托 `initOnRelease`，保证下达与齐套建档原子性。

> **物料上下文事件契约已对齐**：物料上下文已落地，发布 `material.bom.lifecycle` / `material.inventory.changed` / `material.substitute.lifecycle` / `material.kit.reserved` / `material.kit.released`，本服务订阅后重算 `KitStatus`。BOM 详情（重算时若需）REST 查询物料上下文 `BomReadModel`，不依赖事件载荷携带全量明细。

## 4. 应用服务

应用服务是**外部调用入口**，负责：接收请求 / 事务边界 / 调用领域服务编排 / 发布集成事件。本上下文与在制品执行上下文的协作经**异步事件解耦**（工单下达/状态变更事件）+ **降级查询**（过点缓存未命中 REST 查询工单状态），不在过点主事务中引入分布式事务。

### 4.1 WorkOrderCommandAppService（工单命令应用服务）

**职责**：处理工单审核下达、变更、暂停/恢复、取消的写操作命令（REST/终端入口，发命令者：计划员/生产主管）。

```yaml
WorkOrderCommandAppService:
  方法:
    # ─── 审核下达 ───
    reviewAndReleaseWorkOrder(work_order_id, released_by):
      # -> WorkOrderReleaseService.reviewAndRelease
      # 同事务：版本绑定 + 流水号生成 + 产品流水号批量生成 + Outbox

    # ─── 工单变更 ───
    changeWorkOrder(work_order_id, changed_fields, change_reason):
      # -> WorkOrder.change（聚合内校验：IN_PROGRESS 禁调 target_qty INV-16；RELEASED/IN_PROGRESS 禁变绑定 INV-07）
      # 变更拒绝时 -> WorkOrder.rejectQuantityChange / rejectBindingChange

    # ─── 状态流转 ───
    pauseWorkOrder(work_order_id, pause_reason):
      # -> WorkOrder.pause(pause_reason) -> WorkOrderPaused -> wo.order.paused
    resumeWorkOrder(work_order_id):
      # -> WorkOrder.resume() -> WorkOrderResumed -> wo.order.resumed

    # ─── 取消 ───
    cancelWorkOrder(work_order_id, cancel_reason, authorized_by?, in_progress_sn_disposal?):
      # 前置：IN_PROGRESS 时需授权记录 + 在制 SN 处理方式（INV-CX-02）
      # -> WorkOrder.cancel(...) -> WorkOrderCancelled -> wo.order.cancelled
```

| 用例 | 事务边界 | 调用领域对象 | 产出事件 | 幂等策略 |
|------|----------|--------------|----------|----------|
| 审核下达 | WorkOrder + ProductSerialNo + KitStatus 同事务 | `WorkOrderReleaseService` + `MesSerialNumberService` + `ProductSerialNoService` + `KitStatusService` | `WorkOrderBindingLocked` + `MesSerialNoGenerated` + `WorkOrderReleased` + `ProductSerialNoBatchGenerated` + `KitStatusChanged`（建档） | `commandId`；`source_event_id` 已去重 |
| 工单变更 | 单聚合事务 | `WorkOrder.change` / `rejectQuantityChange` / `rejectBindingChange` | `WorkOrderChanged` / `WorkOrderQuantityChangeRejected` / `WorkOrderBindingChangeRejected` | `commandId`；`version` |
| 暂停/恢复 | 单聚合事务 | `WorkOrder.pause` / `resume` | `WorkOrderPaused` / `WorkOrderResumed` | `commandId` |
| 取消工单 | 单聚合事务 | `WorkOrder.cancel` | `WorkOrderCancelled` | `commandId`；终态拒收（INV-03） |

> **审核下达用例的事务边界**扩展为「WorkOrder 状态变更 + ProductSerialNo 批量生成 + KitStatus 建档 + Outbox 同事务」。版本绑定失败/流水号生成失败则拒绝下达，不产生半成品状态。

### 4.2 WorkOrderEventConsumeAppService（事件消费应用服务）

**职责**：订阅上下文外事件，翻译为本上下文命令，委托领域服务处理。

```yaml
WorkOrderEventConsumeAppService:
  订阅主题与处理:
    # 在制品执行上下文（主题前缀 mes.*）
    mes.workorder.progress (WorkOrderProgressAccrued):
      -> WorkOrderCompletionService.onWorkOrderProgressAccrued
      # 幂等：(work_order_id, accrued_at) 去重表（BIZ-02）
    mes.checkpoint.lifecycle (CheckpointReleased, 首次过点):
      -> WorkOrder.start() -> WorkOrderStarted
      # 幂等：work_order_id 去重（首次过点转态仅一次 INV-10）

    # 返工上下文（主题前缀 brework.*）
    brework.order.created (BatchReworkOrderCreated):
      -> 维护源工单关联返工只读投影（关联返工工单数、状态摘要）
      # 不改变源工单状态；幂等：rework_order_id 去重

    # 排产上下文（主题前缀 schedule.*）
    schedule.confirmed (ScheduleConfirmed):
      -> WorkOrder.applyMesSchedule(line_id, planned_start_at, planned_finish_at, source_event_id)
      # 回写 MES 排产快照（与 SAP 建议并存 INV-CX-08）；幂等：work_order_id + source_event_id 去重
    schedule.rescheduled (ScheduleRescheduled):
      -> WorkOrder.applyMesSchedule(new_line_id, new_start_at, new_finish_at, source_event_id)
      # 更新 MES 排产快照；幂等：work_order_id + source_event_id 去重
    schedule.released (ScheduleReleased):
      -> WorkOrder.clearMesSchedule(source_event_id)
      # 清空 MES 排产快照；幂等：work_order_id + source_event_id 去重

    # 物料上下文（主题前缀 material.*，齐套重算）
    material.bom.lifecycle (BomActivated / BomDeprecated):
      -> KitStatusService.onMaterialEvent
      # 幂等：work_order_id + source_event_id 去重（BIZ-08）
    material.inventory.changed (InventoryChanged):
      -> KitStatusService.onMaterialEvent
      # 幂等：work_order_id + source_event_id 去重（BIZ-08）
    material.substitute.lifecycle (SubstituteRuleActivated / Deactivated):
      -> KitStatusService.onMaterialEvent
      # 幂等：work_order_id + source_event_id 去重（BIZ-08）
    material.kit.reserved (KitReserved):
      -> KitStatusService.onMaterialEvent
      # 幂等：work_order_id + source_event_id 去重（BIZ-08）
    material.kit.released (KitReleased):
      -> KitStatusService.onMaterialEvent
      # 幂等：work_order_id + source_event_id 去重（BIZ-08）

    # 本上下文 ACL（SAP 消息消费）
    （SAP 工单下发消息，经 WorkOrderReceptionPort 消费）:
      -> WorkOrderReceptionService.receiveSapWorkOrder
      # 幂等：source_event_id 去重表（BIZ-01）
```

> **不直接消费上下文外事件来做状态变更**（INV-CX-03）：本上下文将订阅事件包装为本上下文语义事件（`WorkOrderStarted` / `WorkOrderCompleted` / `WorkOrderClosed`）后发布，下游凭主题前缀 `wo.*` 区分来源。`BatchReworkOrderCreated` 仅维护只读投影，不改变源工单状态。

> **主题命名约定**：本上下文**对外发布**使用 `wo.*` 前缀（`wo` = work order 缩写，与返工上下文 `brework.*` 严格区分，与返修上下文 `rework.*` 严格区分）。本上下文**订阅**使用各发布限界上下文自己的前缀，不重写——`mes.*`（在制品执行上下文）、`brework.*`（返工上下文）、`schedule.*`（排产上下文）、`material.*`（物料上下文，齐套重算）。BOM/工艺路线版本在审核下达时通过 REST 查询锁定快照（非事件订阅）；齐套重算则订阅 `material.*` 事件。

> **制造资源服务主题前缀已对齐**——物料上下文 `material.*` 已订阅（齐套重算 `KitStatus`）；工艺管理上下文仍以 REST 查询为主（绑定工艺路线版本），暂不订阅其事件。前缀以制造资源服务最终约定为准。

## 6. 不变规则（Invariants）

不变规则是领域模型中**必须始终为真**的业务约束，无论经过何种操作序列。按**一致性边界**分为三段，**分别编号、不可混列**（编号在此首次诞生；事件风暴侧以无编号"已识别约束"清单对应，见 [事件风暴 - 工单管理上下文](../事件风暴/工单管理上下文.md#已识别约束)）：

- **聚合不变式（`INV-XX`）**：落在单一聚合的一致性边界内，事务内强一致、始终为真，由聚合根前置条件 / 状态机 / 规约守护，**按所属聚合根分子节归位**。
- **业务不变式（`BIZ-XX`）**：本上下文内跨聚合 / 跨实例，一致性边界与任意单事务无法重合，最终一致，由领域服务 + 唯一索引 / 事件去重表 / Saga 守护，**禁止挂在聚合根上**。
- **跨上下文不变式（`INV-CX`）**：跨限界上下文，最终一致，由事件订阅 + ACL + 跨服务协调守护（同服务部署时可走本地事务强一致，见各条说明）。

### 6.1 聚合不变式（Aggregate Invariants）

按所属聚合根分子节归位。

#### 6.1.1 WorkOrder（工单）

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-01 | 下达前必须绑定 BOM 版本 + 工艺路线版本（`bom_binding` / `route_binding` 非空） | `WorkOrder.reviewAndRelease` 前置；`WorkOrderReleaseService` 编排保证 |
| INV-03 | `CLOSED` / `CANCELLED` 为终态，之后任何事件均拒收 | `WorkOrderStatus` 状态机 |
| INV-06 | 状态单向流转，仅 `PauseWorkOrder` / `ResumeWorkOrder` 允许回退 | `WorkOrderStatus` 状态机 |
| INV-07 | 版本绑定在 `ReviewAndReleaseWorkOrder` 时锁定（`bom_version` / `route_version` 快照）；`RELEASED` / `IN_PROGRESS` 后禁止直接变更 BOM 或工艺路线版本，若已在制后需修改产品 BOM 或工艺路线，则走返工流程 | `WorkOrderBinding` 值对象快照 + `WorkOrder.change` 前置校验；拒绝时发出 `WorkOrderBindingChangeRejected` |
| INV-10 | 首次过点自动转态 `RELEASED -> IN_PROGRESS`——消费 `CheckpointReleased`（首次过点），`work_order_id` 去重，首次过点转态仅一次 | `WorkOrderEventConsumeAppService` 消费 + `work_order_id` 去重 |
| INV-11 | `COMPLETED` 后立即自动 `CLOSED`，不允许跳过完工口径直接 `CLOSED` | `WorkOrderCompletionService` 自动编排；完工产品数量未达标不能直接结案 |
| INV-13 | 当前阶段一张 SAP 工单仅允许一个有效 MES 工单流水号，模型保留同一 SAP 工单多个 `mes_serial_no` 的扩展空间 | `WorkOrder` 聚合内 `mes_serial_no` 唯一 |
| INV-15 | 当前阶段一张工单仅允许一个产品明细，多产品明细暂不启用 | `WorkOrderItem` 值对象单产品设计；事件与完工判定按单产品口径 |
| INV-16 | `IN_PROGRESS` 后禁止调整 `target_qty` | `WorkOrder.change` 前置校验；拒绝时发出 `WorkOrderQuantityChangeRejected` |

> **已确认：工单状态缓存以事件投影为主，REST 查询兜底**——在制品执行上下文订阅 `wo.order.*` 维护 `WorkOrderStatusCache`，正常过点链路优先读取本地缓存进行工单状态校验，避免每次过点同步调用工单管理影响产线节拍。缓存未命中、缓存过期或事件版本不可信时，同步 REST 查询本上下文兜底；查询成功后刷新缓存并继续判定。若 REST 查询失败，则保守拦截本次过点（INV-CX-05）。

## 9. 领域服务与应用服务的关系

```
┌──────────────────────────────────────────────────────────────────────┐
│                           外部调用入口                                  │
│                                                                      │
│  REST/终端 ──▶ WorkOrderCommandAppService (应用服务)                  │
│                ├─ 单聚合操作：直接委托聚合根方法                        │
│                ├─ 跨聚合编排：委托领域服务（接收/下达/完工/流水号）      │
│                └─ 同事务推进状态 + 发布集成事件（Outbox）               │
│                                                                      │
│  消息消费 ───▶ WorkOrderEventConsumeAppService (应用服务)             │
│                └─ 翻译 mes.*/brework.*/material.*/schedule.* 事件 -> 委托领域服务             │
│                  （包装为本上下文语义事件后发布，INV-CX-03）                │
│                                                                      │
│  查询请求 ───▶ WorkOrderQueryAppService (应用服务，读模型)            │
│                └─ 直接查询读模型投影（工单状态/进度/关联返工）          │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           领域服务层                                    │
│  WorkOrderReceptionService │ WorkOrderReleaseService                   │
│  WorkOrderCompletionService │ MesSerialNumberService                   │
│  ProductSerialNoService │ KitStatusService                            │
│  └─ 封装跨聚合规则，加载聚合，调用聚合行为，写仓储，返回领域事件          │
└──────────────────────────────────────────────────────────────────────┘
                              |
                              v
┌──────────────────────────────────────────────────────────────────────┐
│                           聚合根（领域层）                              │
│  WorkOrder / ProductSerialNo / KitStatus                                          │
│  └─ 表达业务状态、行为、不变式、领域事件；不依赖 Spring/MQ/HTTP          │
└──────────────────────────────────────────────────────────────────────┘
```

**原则**：
- 应用服务不包含业务逻辑，只做编排和事务边界（CLAUDE.md 分层）
- 领域服务封装跨聚合的业务规则，每个领域服务必答"为什么不放在聚合根内"
- 聚合根内的业务逻辑由聚合根自身保证，行为是业务动词方法（非 `update/save` 流水账）
- 不变式由聚合根 + 领域服务 + 唯一索引/事件去重表共同守护
- 工单状态与在制品执行经异步事件解耦 + 降级查询（INV-CX-05），不在过点主事务中引入分布式事务
