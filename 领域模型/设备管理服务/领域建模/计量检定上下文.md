# 计量检定上下文 — 领域建模（Calibration Domain Model）

> **限界上下文**：计量检定上下文
> **统一语言**：CalibrationRule（检定规则）, CalibrationPlan（检定计划）, CalibrationTask（检定任务）, CalibrationCertificate（检定证书）, CalibrationResult（检定结果）, ExternalLab（外部检定机构）, CalibrationHistory（检定历史）, RepairFeasibility（处置可行性）, LeadTime（送检提前期）
> **建模依据**：[事件风暴 — 计量检定上下文](../事件风暴/计量检定上下文.md)

## 0. 建模总览

本域是设备管理服务下的**计量管理子域**，是 PCBA + 整机组装混合型车间所有"计量器具检定活动"的管理权威源。核心职责是管理**检定规则定义、周期检定计划、送检/收回流程、证书签发与过期预警**。

## 1. 聚合根

### 1.1 CalibrationRule（检定规则）

**一致性边界**：单条检定规则的定义——规定某类计量器具的检定周期、方式、检定项目与 ABC 分类。

**职责**：按器具分类定义周期/方式/项目；ABC 分类决定管理严格度；作为周期检定计划生成的唯一依据。

```yaml
CalibrationRule:
  # ─── 标识 ───
  rule_id:                RuleId                    # 规则唯一标识（聚合根ID）

  # ─── 适用范围 ───
  target_classification:  String                    # 计量器具分类（如"卡尺""扭矩扳手""温度计"）
  abc_category:           AbcCategory               # ABC 分类（A/B/C）

  # ─── 检定参数 ───
  calibration_cycle:      Integer                   # 检定周期（月）
  calibration_method:     CalibrationMethod         # 检定方式（INTERNAL/EXTERNAL）
  external_lab_id:        ExternalLabReference?     # 外部检定机构（外检时必填）

  # ─── 检定项目模板 ───
  calibration_items:      List<CalibrationItem>     # 检定项目模板列表

  # ─── 证书与提前期 ───
  certificate_template:   String?                   # 证书模板（内检时）
  lead_time_days:         Integer                   # 送检提前期（天）

  # ─── 管理属性 ───
  responsible_role:       String                    # 负责角色
  status:                 RuleStatus                # 规则状态
  enabled:                Boolean                   # 是否启用
```

**行为**：
- `define(target_classification, abc_category, cycle, method, calibration_items, lead_time_days)` -> 发出 `CalibrationRuleDefined`
- `update(changed_fields)` -> 发出 `CalibrationRuleUpdated`（变更从下个周期生效，已生成的计划/任务不受影响）
- `activate()` -> 发出 `RuleActivated`（前置：检定项目模板非空，当前 DRAFT 或 DEACTIVATED）
- `deactivate()` -> 发出 `RuleDeactivated`（前置：当前 ACTIVE）
- `obsolete()` -> 发出 `RuleObsoleted`（终态，之后任何事件均拒收）

**状态机**：

```
            Define
              |
              v
          +--------+   Activate    +--------+   Deactivate   +--------------+
          | DRAFT  |-------------->| ACTIVE |---------------->| DEACTIVATED  |
          +--------+               +--------+                 +--------------+
              |                        ^                          |
              |                        |    Activate              |
              |                        +--------------------------+
              |
              |  Obsolete（终态）
              v
          +----------+
          | OBSOLETE |  终态——之后任何事件均拒收
          +----------+
```

| 边 | 命令 | 前置条件 | 谁来发命令 |
|----|------|---------|-----------|
| DRAFT -> ACTIVE | activate() | 检定项目模板非空 | 计量管理员 |
| ACTIVE -> DEACTIVATED | deactivate() | 当前 ACTIVE | 计量管理员 / 台账上下文 `AssetRetired` 消费 |
| DEACTIVATED -> ACTIVE | activate() | 当前 DEACTIVATED | 计量管理员 |
| 任意非终态 -> OBSOLETE | obsolete() | — | 计量管理员 |
| OBSOLETE 之后 | （任何） | 终态，拒收 | — |

### 1.2 CalibrationPlan（检定计划）

**一致性边界**：单个周期内的检定计划汇总——将多条 `CalibrationDue` 汇总为一个计划，每条明细关联规则与器具。

**职责**：接收到期事件后汇总生成计划；跟踪计划整体完成状态；每条 plan_item 拆解为独立 CalibrationTask。

```yaml
CalibrationPlan:
  # ─── 标识 ───
  plan_id:                PlanId                    # 计划唯一标识（聚合根ID）

  # ─── 计划明细 ───
  plan_items:             List<PlanItem>            # 计划明细列表

  # ─── 计划周期 ───
  plan_horizon:           String                    # 计划周期（如 2026-W24）

  # ─── 状态 ───
  status:                 PlanStatus                # 计划状态

  # ─── 审计 ───
  generated_at:           DateTime                  # 生成时间
```

**PlanItem 实体**：

```yaml
PlanItem:
  instrument_id:          AssetId                   # 目标器具
  rule_id:                RuleId                    # 来源规则
  due_reason:             DueReason                 # 到期原因
  deadline:               DateTime                  # 执行截止时间
```

**行为**：
- `generate(plan_items, plan_horizon)` -> 发出 `CalibrationPlanGenerated`
- `activate()` -> 发出 `CalibrationPlanActivated`（DRAFT -> ACTIVE）
- `markItemCompleted(task_id)` -> 更新单条明细完成状态；若全部完成 -> `COMPLETED`；若部分完成 -> `PARTIALLY_COMPLETED`
- `markOverdue()` -> 发出 `CalibrationPlanOverdue`（ACTIVE -> OVERDUE，deadline 到期仍未全部完成）

**状态机**：

```
    DRAFT ──Activate──▶ ACTIVE ──┬── 全部完成 ──▶ COMPLETED (终态)
                                 │
                                 ├── 部分完成 ──▶ PARTIALLY_COMPLETED
                                 │
                                 └── deadline 到期 ──▶ OVERDUE
```

### 1.3 CalibrationTask（检定任务）

**一致性边界**：单次检定执行单元——从任务创建到器具收回的完整生命周期。

**职责**：承载单台器具的单次检定执行流；内检/外检分支；送检即触发暂停使用；PASS 后签发证书，FAIL 后记录处置可行性。

```yaml
CalibrationTask:
  # ─── 标识 ───
  task_id:                TaskId                    # 任务唯一标识（聚合根ID）

  # ─── 关联 ───
  instrument_id:          AssetId                   # 目标器具
  rule_id:                RuleId                    # 来源规则
  plan_id:                PlanId?                   # 来源计划（可为空，紧急检定无计划）

  # ─── 检定方式 ───
  method:                 CalibrationMethod         # 检定方式（INTERNAL/EXTERNAL）

  # ─── 调度信息 ───
  assignee:               String?                   # 指派人/责任角色
  deadline:               DateTime                  # 执行截止时间

  # ─── 送检信息 ───
  dispatched_at:          DateTime?                 # 送检时间
  expected_return_date:   DateTime?                 # 预计收回日期

  # ─── 检定结果 ───
  result:                 CalibrationResult?        # 检定结果（PASS/FAIL）
  failed_items:           List<CalibrationItem>?    # 不合格项目（FAIL 时）
  repair_feasibility:     RepairFeasibility?        # 处置可行性（FAIL 时）

  # ─── 收回信息 ───
  received_at:            DateTime?                 # 收回时间
  received_by:            String?                   # 收回人

  # ─── 状态 ───
  status:                 TaskStatus                # 任务状态
```

**行为**：
- `schedule(instrument_id, rule_id, method, deadline, plan_id?)` -> 发出 `CalibrationTaskCreated`
- `dispatch(dispatched_at, expected_return_date)` -> 发出 `CalibrationDispatched`（前置：PENDING）
- `performInternalCalibration(items, results)` -> 发出 `InternalCalibrationPerformed`（前置：DISPATCHED 且 method=INTERNAL）
- `issueInternalCertificate(cert_no, valid_until)` -> 发出 `CalibrationCertificateIssued`（前置：DISPATCHED 且 result=PASS 且 method=INTERNAL）
- `recordCalibrationFailed(failed_items, repair_feasibility)` -> 发出 `CalibrationFailed`（前置：DISPATCHED 且 result=FAIL 且 method=INTERNAL）
- `registerExternalCertificate(cert_no, valid_until, external_lab_id, issued_by)` -> 发出 `CalibrationCertificateIssued`（前置：DISPATCHED 且 method=EXTERNAL）
- `recordExternalCalibrationFailed(failed_items, external_lab_id, repair_feasibility)` -> 发出 `CalibrationFailed`（前置：DISPATCHED 且 method=EXTERNAL）
- `receive(received_at, received_by)` -> 发出 `InstrumentCalibrationReceived`（前置：CERT_ISSUED 或 FAILED）
- `cancel(reason)` -> 发出 `CalibrationTaskCancelled`（前置：任意非终态；仅资产退役/报废触发）

**状态机**：

```
                     PENDING
                        |
              ┌─────────┴────────── 报废/退役 Cancel（任意非终态）──────────┐
              │                     │                                      │
              │           送检 Dispatch                                    │
              │           (前置: PENDING)                                  │
              │                     │                                      │
              │                     v                                      │
              │             DISPATCHED ────────────── Cancel ──────────────┤
              │                     │                                      │
              │   内检执行 / 登记外检结果                                   │
              │   (前置: DISPATCHED)                                       │
              │                     │                                      │
              │              ┌──────┴───────┐                              │
              │              v               v                             │
              │        CERT_ISSUED       FAILED                            │
              │     (PASS, 已签发证书)   (检定不合格)                       │
              │              │               │                             │
              │       收回 Receive      收回 Receive                        │
              │       (前置: CERT_ISSUED) (前置: FAILED)                    │
              │              │               │                             │
              │              v               v                             │
              └────────▶ RECEIVED ◀────────────────────────────────────────┘
                              (终态)
```

| 边 | 命令 | 前置条件 | 谁来发命令 |
|----|------|---------|-----------|
| PENDING -> DISPATCHED | dispatch() | 当前 PENDING | 调度引擎（计划激活后）/ 计量管理员 |
| DISPATCHED -> CERT_ISSUED | issueInternalCertificate() / registerExternalCertificate() | 当前 DISPATCHED 且 result=PASS | 内检员 / 计量管理员 |
| DISPATCHED -> FAILED | recordCalibrationFailed() / recordExternalCalibrationFailed() | 当前 DISPATCHED 且 result=FAIL | 内检员 / 计量管理员 |
| CERT_ISSUED -> RECEIVED | receive() | 当前 CERT_ISSUED | 计量管理员（物理回位登记） |
| FAILED -> RECEIVED | receive() | 当前 FAILED | 计量管理员 |
| RECEIVED 之后 | （任何） | 终态，拒收 | — |
| 任意非终态 -> CANCELLED | cancel() | 资产退役/报废 | 台账上下文 `AssetRetired` 消费后触发 |

### 1.4 CalibrationCertificate（检定证书）

**一致性边界**：单张检定证书——从签发到过期/撤销的完整生命周期。

**职责**：证书签发、有效期维护、过期检测；本上下文为证书有效期权威源；过期触发冻结。

```yaml
CalibrationCertificate:
  # ─── 标识 ───
  cert_no:                String                    # 证书编号（全局唯一，聚合根ID）

  # ─── 关联 ───
  instrument_id:          AssetId                   # 计量器具 ID
  task_id:                TaskId                    # 关联检定任务

  # ─── 签发信息 ───
  issued_by:              String                    # 签发机构（内部 / 外部实验室名称）
  issued_at:              DateTime                  # 签发日期
  external_lab_id:        ExternalLabReference?     # 外部实验室 ID（外检时）

  # ─── 有效期 ───
  valid_from:             DateTime                  # 有效起始日期
  valid_until:            DateTime                  # 有效截止日期

  # ─── 检定结果 ───
  calibration_result:     CalibrationResult         # 检定结果（仅 PASS 才签发证书）
  calibration_items:      List<CalibrationItem>     # 检定项目与结果

  # ─── 附件 ───
  attachment_urls:        List<String>              # 证书扫描件/电子证书

  # ─── 状态 ───
  status:                 CertificateStatus         # 证书状态
```

**行为**：
- `issue(cert_no, instrument_id, task_id, issued_by, valid_from, valid_until, calibration_items, attachment_urls?)` -> 发出 `CalibrationCertificateIssued`
- `markExpiringSoon()` -> 发出 `CalibrationExpiringSoon`（VALID -> EXPIRING_SOON，由定时器触发）
- `markExpired()` -> 发出 `CalibrationExpired`（EXPIRING_SOON -> EXPIRED，由定时器触发；终态）
- `revoke(reason)` -> 发出 `CalibrationCertificateRevoked`（VALID -> REVOKED，终态）

**状态机**：

```
    VALID ──(valid_until - lead_time_days ≤ now)──▶ EXPIRING_SOON ──(valid_until ≤ now)──▶ EXPIRED
      │                                                    │
      │  Revoke                                            │  Revoke
      v                                                    v
    REVOKED (终态)                                    REVOKED (终态)
```

| 边 | 触发条件 | 谁来发命令 | 后续 |
|----|---------|-----------|------|
| VALID -> EXPIRING_SOON | `valid_until - lead_time_days ≤ now` | 本上下文定时器 | 发布 CalibrationExpiringSoon，通知 |
| EXPIRING_SOON -> EXPIRED | `valid_until ≤ now` | 本上下文定时器 | 发布 CalibrationExpired；台账上下文冻结；本上下文触发紧急检定 |
| VALID/EXPIRING_SOON -> REVOKED | 证书作废（如签发错误） | 计量管理员 | 终态，拒收 |
| EXPIRED/REVOKED 之后 | （任何） | 终态，拒收 | — |

## 2. 值对象

### 2.1 RuleId（规则唯一标识）

```yaml
RuleId:
  value: String    # UUID 或数据库序列生成的唯一标识
```

> 不可变。由系统在 `CalibrationRuleDefined` 事件时生成。

### 2.2 PlanId（计划唯一标识）

```yaml
PlanId:
  value: String    # UUID 或数据库序列生成的唯一标识
```

> 不可变。由系统在 `CalibrationPlanGenerated` 事件时生成。

### 2.3 TaskId（任务唯一标识）

```yaml
TaskId:
  value: String    # UUID 或数据库序列生成的唯一标识
```

> 不可变。由系统在 `CalibrationTaskCreated` 事件时生成。

### 2.4 AbcCategory（ABC 分类）

```yaml
AbcCategory:
  - A    # 强制检定——必须外检到法定机构，超期立即冻结 + 法规违规告警
  - B    # 依法管理——可内检或外检，超期冻结，无法规违规告警
  - C    # 免检/一次性——首件检定后免周期检定，无周期检定要求
```

> 不可变枚举。由 `CalibrationRule` 在 `define` 时确定，之后不可直接修改——需 `obsolete` 旧规则 + `define` 新规则。

### 2.5 CalibrationMethod（检定方式）

```yaml
CalibrationMethod:
  - INTERNAL    # 内检——在厂内完成，内检员执行
  - EXTERNAL    # 外检——送外部检定机构，需物理离开车间
```

> 不可变枚举。在 `CalibrationRule` 定义时确定，`CalibrationTask` 创建时从规则继承。

### 2.6 DueReason（到期原因）

```yaml
DueReason:
  - CERT_EXPIRING    # 证书临期——valid_until - lead_time_days ≤ now
  - CYCLE_REACHED    # 日历周期到达——距上次检定达到 calibration_cycle
  - CERT_EXPIRED     # 证书已过期——valid_until ≤ now，紧急检定
```

> 不可变枚举。由 `CalibrationDueDetectionService` 判定后写入事件载荷。

### 2.7 CalibrationResult（检定结果）

```yaml
CalibrationResult:
  - PASS    # 检定合格
  - FAIL    # 检定不合格
```

> 不可变枚举。由内检员/计量管理员在检定执行时判定。

### 2.8 RepairFeasibility（处置可行性）

```yaml
RepairFeasibility:
  - RECALIBRATABLE    # 可重新调校——安排下次检定
  - NOT_ECONOMICAL    # 维修不经济——可发起报废审批
  - NOT_REPAIRABLE    # 无法修复——可发起报废审批
```

> 不可变枚举。仅在 `CalibrationFailed` 时填写，由内检员/计量管理员判定。

### 2.9 RuleStatus（规则状态）

```yaml
RuleStatus:
  - DRAFT          # 草稿
  - ACTIVE         # 已激活
  - DEACTIVATED    # 已停用
  - OBSOLETE       # 已废弃（终态）
```

> 状态机驱动，仅通过领域事件变更。

### 2.10 PlanStatus（计划状态）

```yaml
PlanStatus:
  - DRAFT                 # 已生成，未激活
  - ACTIVE                # 已激活，执行中
  - PARTIALLY_COMPLETED   # 部分完成
  - COMPLETED             # 全部完成（终态）
  - OVERDUE               # 已超期
```

> 状态机驱动，仅通过领域事件变更。

### 2.11 TaskStatus（任务状态）

```yaml
TaskStatus:
  - PENDING       # 待执行
  - DISPATCHED    # 已送检
  - CERT_ISSUED   # 已签发证书（PASS）
  - FAILED        # 检定不合格
  - RECEIVED      # 已收回（终态）
  - CANCELLED     # 已取消（终态，仅资产退役/报废）
```

> 状态机驱动，仅通过领域事件变更。

### 2.12 CertificateStatus（证书状态）

```yaml
CertificateStatus:
  - VALID            # 有效
  - EXPIRING_SOON    # 即将过期
  - EXPIRED          # 已过期（终态）
  - REVOKED          # 已撤销（终态）
```

> 状态机驱动，仅通过领域事件变更。

### 2.13 CalibrationItem（检定项目）

```yaml
CalibrationItem:
  item_name:          String      # 项目名称
  standard_value:     String      # 标准值
  tolerance:          String      # 允差
  measurement_unit:   String      # 单位
  actual_value:       String?     # 实测值（执行时填写）
  result:             CalibrationResult?  # 单项结果（执行时填写）
```

> 在 `CalibrationRule` 中作为模板存在（仅 `item_name`, `standard_value`, `tolerance`, `measurement_unit`）；在 `CalibrationTask` 执行时填写 `actual_value` 和 `result`。

### 2.14 ExternalLabReference（外部实验室引用）

```yaml
ExternalLabReference:
  lab_id:       String      # 实验室唯一标识
  lab_name:     String      # 实验室名称
  accreditation: String?    # 资质编号
```

> 不可变值对象。本上下文不管理外部实验室主数据，仅引用其标识与名称。

### 2.15 PlanItem（计划明细）

```yaml
PlanItem:
  instrument_id:    AssetId       # 目标器具
  rule_id:          RuleId        # 来源规则
  due_reason:       DueReason     # 到期原因
  deadline:         DateTime      # 执行截止时间
  task_id:          TaskId?       # 拆解后关联的任务 ID
  completed:        Boolean       # 是否已完成
```

> 隶属于 `CalibrationPlan` 聚合的实体，生命周期与计划绑定。

## 3. 领域服务

领域服务封装**跨聚合**的业务逻辑或**不自然归属**单一聚合根的操作。

### 3.1 CalibrationDueDetectionService（检定到期检测服务）

**职责**：封装检定到期的判定逻辑——扫描证书有效期与日历周期，决定何时触发 `CalibrationDue`。

```yaml
CalibrationDueDetectionService:
  方法:
    scanCertificatesForExpiry():
      # 定时器驱动，扫描所有 VALID 状态的证书
      # 判定逻辑：
      #   - valid_until - 30 天 ≤ now -> 通知计量管理员（预警，不触发 Due）
      #   - valid_until - lead_time_days ≤ now -> CalibrationDue(due_reason=CertExpiring)
      #   - valid_until ≤ now -> CalibrationDue(due_reason=CertExpired)
      # 注意：主触发使用本上下文自身的证书数据，不依赖台账上下文

    scanRulesForCycle():
      # 定时器驱动，扫描所有 ACTIVE 状态的规则 + 关联器具
      # 判定逻辑：距上次检定 ≥ calibration_cycle -> CalibrationDue(due_reason=CycleReached)
      # 上次检定时间从 CalibrationCertificate 的 issued_at 获取

    supplementFromCertValidityUpdate(instrument_id, cert_no, valid_until):
      # 台账上下文 InstrumentCertValidityUpdated 事件消费入口
      # 仅当新有效期触发临期/过期判定时补充触发 MarkCalibrationDue
      # 主触发为本上下文定时器，此方法为补充校验
      # 幂等：以 (instrument_id, cert_no, valid_until) 去重
```

> **为什么不放在聚合根内**：到期检测需要扫描多个聚合（CalibrationCertificate + CalibrationRule + CalibrationTask），是跨聚合的查询与判定，不自然归属单一聚合根。

### 3.2 CalibrationPlanGenerationService（检定计划生成服务）

**职责**：将 `CalibrationDue` 事件汇总为 `CalibrationPlan`，并拆解为 `CalibrationTask`。

```yaml
CalibrationPlanGenerationService:
  方法:
    generatePlan(due_events: List<CalibrationDue>):
      # 1. 将多条 CalibrationDue 按 plan_horizon 汇总为一个 CalibrationPlan
      # 2. 每条 CalibrationDue -> 一条 PlanItem
      # 3. 校验 INV-P1：每条 plan_item 必须关联已激活的 CalibrationRule
      # 4. 校验 INV-P2：plan 内 instrument 不重复
      # 5. 创建 CalibrationPlan 聚合根，发出 CalibrationPlanGenerated

    activatePlanAndDispatchTasks(plan: CalibrationPlan):
      # 1. plan.activate() -> CalibrationPlanActivated
      # 2. 对每条 plan_item，调用 dispatchTasks()
      # 3. 更新 plan 完成状态

    dispatchTasks(plan: CalibrationPlan):
      # 对每条 plan_item：
      # 1. 校验 INV-C3：查询读模型确认该器具无未完成检定任务
      #    + 数据库唯一索引 (instrument_id, status ∈ {PENDING, DISPATCHED}) 兜底
      # 2. 若已存在重复任务 -> 合并而非重复创建
      # 3. 创建 CalibrationTask 聚合根，发出 CalibrationTaskCreated
```

> **为什么不放在聚合根内**：计划生成涉及创建 CalibrationPlan + 多个 CalibrationTask，跨聚合的一致性编排由领域服务承担。

### 3.3 CalibrationExecutionService（检定执行服务）

**职责**：封装检定执行流程——内检/外检分支、结果判定、证书签发、台账上下文交互。

```yaml
CalibrationExecutionService:
  方法:
    dispatchTask(task_id, expected_return_date):
      # 1. 加载 CalibrationTask -> task.dispatch()
      # 2. CalibrationDispatched 发布到 calibration.task.dispatched
      #    -> 台账上下文消费：SuspendAsset(reason=Calibrating)

    performInternalCalibration(task_id, items, results):
      # 1. 加载 CalibrationTask -> task.performInternalCalibration(items, results)
      # 2. 若 result=PASS -> issueInternalCertificate(task_id, cert_no, valid_until)
      # 3. 若 result=FAIL -> task.recordCalibrationFailed(failed_items, repair_feasibility)
      #    -> CalibrationFailed 发布到 calibration.task.failed
      #    -> 台账上下文消费：SuspendAsset(reason=CalibrationFailed)

    issueInternalCertificate(task_id, cert_no, valid_until):
      # 1. 校验 INV-T2：calibration_result 必须为 PASS
      # 2. 校验 INV-T3：valid_until > issued_at
      # 3. 创建 CalibrationCertificate 聚合根
      # 4. CalibrationCertificateIssued 发布到 calibration.certificate.issued
      #    -> 台账上下文消费：RefreshCertValidity + ClearBlocking(CALIBRATION_*) + RecomputeAndDecideReinstate

    registerExternalCertificate(task_id, cert_no, valid_until, external_lab_id, issued_by):
      # 同上，但证书来源为外部实验室

    recordExternalCalibrationFailed(task_id, failed_items, external_lab_id, repair_feasibility):
      # 1. 加载 CalibrationTask -> task.recordExternalCalibrationFailed(...)
      # 2. CalibrationFailed 发布到 calibration.task.failed
      #    -> 台账上下文消费：SuspendAsset(reason=CalibrationFailed)
      #    -> feasibility 为 NOT_ECONOMICAL/NOT_REPAIRABLE 时，台账上下文可发起报废审批

    receiveInstrument(task_id, received_by):
      # 1. 加载 CalibrationTask -> task.receive(now(), received_by)
      # 2. InstrumentCalibrationReceived 发布
      #    对 PASS：补充记录（物理回位登记），资产可用性已由 CalibrationCertificateIssued 恢复
      #    对 FAIL：器具收回但资产仍冻结，等待处置决策
```

> **设计说明**：此服务封装了检定执行的核心流程，包括内检/外检分支、证书签发，以及通过事件契约与台账上下文的协作。台账上下文对 `CalibrationCertificateIssued` 的处理是 `RefreshCertValidity + ClearBlockingByCategory(CALIBRATION_*) + RecomputeAndDecideReinstate`——本上下文只发布事件，不直接指挥台账上下文恢复资产。

### 3.4 CalibrationCertificateLifecycleService（证书生命周期服务）

**职责**：封装证书过期检测与预警——扫描证书有效期，驱动状态流转与通知。

```yaml
CalibrationCertificateLifecycleService:
  方法:
    scanAndMarkExpiring():
      # 定时器驱动，扫描所有 VALID 状态的证书
      # 判定逻辑：
      #   - valid_until - 30 天 ≤ now -> 发布预警通知（不变更状态）
      #   - valid_until - lead_time_days ≤ now -> cert.markExpiringSoon()
      #     -> CalibrationExpiringSoon 发布到 calibration.certificate.expiring
      #     -> 通知服务消费

    scanAndMarkExpired():
      # 定时器驱动，扫描所有 EXPIRING_SOON 状态的证书
      # 判定逻辑：valid_until ≤ now -> cert.markExpired()
      #   -> CalibrationExpired 发布到 calibration.certificate.expired
      #   -> 台账上下文消费：SuspendAsset(reason=CalibrationExpired)
      #   -> 本上下文自动触发 CalibrationDue(due_reason=CertExpired) 紧急检定
```

> **过期预警策略**：

| 预警级别 | 触发条件 | 状态变更 | 动作 |
|---------|---------|---------|------|
| 预警（黄色） | `valid_until - 30 天 ≤ now` | 无 | 通知计量管理员，准备送检 |
| 临期（橙色） | `valid_until - lead_time_days ≤ now` | VALID -> EXPIRING_SOON | 自动触发 CalibrationDue(due_reason=CertExpiring) |
| 过期（红色） | `valid_until ≤ now` | EXPIRING_SOON -> EXPIRED | 台账上下文冻结资产；本上下文触发紧急检定 |

## 6. 不变规则（Invariants）

不变规则是领域模型中**必须始终为真**的业务约束，无论经过何种操作序列。

### 6.1 规则不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-R1 | 同一 `target_classification` 不可有重复规则 | 由 `CalibrationCommandService` 查询读模型 + 数据库唯一索引保证 |
| INV-R2 | `calibration_cycle > 0` | 检定周期必须为正整数，聚合根 `define` 行为内校验 |
| INV-R3 | `method=EXTERNAL` 时 `external_lab_id` 必填 | 聚合根 `define` 行为内校验 |
| INV-R4 | 规则变更从下个周期生效，已生成的计划/任务不受影响 | 快照语义——计划/任务创建时已锁定规则内容 |

### 6.2 计划不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-P1 | 每条 `plan_item` 必须关联已激活的 `CalibrationRule` | `CalibrationPlanGenerationService` 生成时校验 |
| INV-P2 | 同一 plan 内 `instrument_id` 不重复 | 由 `CalibrationPlan` 聚合根行为保证 |

### 6.3 任务不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-C1 | `cert_no` 全局唯一 | 数据库唯一索引 `(cert_no)`，非聚合根自身可校验 |
| INV-C2 | `RECEIVED` / `CANCELLED` 为终态，之后任何事件均拒收 | `CalibrationTask` 聚合根状态机保证 |
| INV-C3 | 同一器具同一时间不可有重复未完成检定任务 | `CalibrationPlanGenerationService` 创建前查询读模型 + 数据库唯一索引 `(instrument_id, status ∈ {PENDING, DISPATCHED})` 共同保证 |
| INV-C4 | 送检后必须记录结果才能收回；PASS 必须签发证书 | `CalibrationTask` 聚合根状态机 + `CalibrationExecutionService` 保证 |
| INV-C5 | 资产退役时取消未执行任务 | 消费 `AssetRetired` 后 `cancel()` 触发，跨上下文不变式，由事件订阅 + 任务状态机共同保证 |
| INV-C6 | 上下文外事件幂等消费 | 事件去重表 `(source, event_id)` + 业务键去重 |

### 6.4 证书不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-T1 | `cert_no` 全局唯一 | 同 INV-C1，数据库唯一索引 `(cert_no)` |
| INV-T2 | 签发时 `calibration_result` 必须为 `PASS` | `CalibrationCertificate` 聚合根 `issue` 行为内校验 |
| INV-T3 | `valid_until > issued_at` | 有效期截止日必须晚于签发日期，聚合根 `issue` 行为内校验 |
| INV-T4 | `EXPIRED` / `REVOKED` 为终态，之后任何事件均拒收 | `CalibrationCertificate` 聚合根状态机保证 |

### 6.5 跨域协作不变式

| 编号 | 不变式 | 说明 |
|------|--------|------|
| INV-D1 | 本上下文是证书有效期权威源 | 证书过期检测由本上下文定时器独立执行，不依赖台账上下文事件触发 |
| INV-D2 | 本上下文只发布事件，不直接指挥台账上下文恢复/冻结资产 | 台账上下文消费 `CalibrationCertificateIssued` / `CalibrationFailed` / `CalibrationExpired` 后自行决策 |
| INV-D3 | 送检 = 暂停使用 | 本上下文发布 `CalibrationDispatched` -> 台账上下文 `SuspendAsset(reason=Calibrating)` |
| INV-D4 | FAIL 后器具保持冻结 | 收回事件仅作物理回位登记，资产冻结状态由台账上下文维护 |

                    ┌──────────────────────────────┐

## 9. 领域服务与应用服务的关系

```
┌──────────────────────────────────────────────────────────────────┐
│                        外部调用入口                               │
│                                                                  │
│  REST API ──▶ CalibrationCommandService (应用服务)                │
│               ├─ 单聚合操作：直接委托聚合根方法                    │
│               └─ 跨聚合编排：委托领域服务                         │
│                                                                  │
│  定时器 ──▶ CalibrationSchedulerService (应用服务)               │
│               ├─ 委托 CalibrationDueDetectionService              │
│               └─ 委托 CalibrationCertificateLifecycleService      │
│                                                                  │
│  消息消费 ──▶ CalibrationEventConsumer (应用服务)                │
│               └─ 仅处理跨服务事件                                 │
│                                                                  │
│  查询请求 ──▶ CalibrationQueryService (应用服务，读模型)          │
│               └─ 直接查询读模型投影                               │
└──────────────────────────────────────────────────────────────────┘
```

**原则**：
- 应用服务不包含业务逻辑，只做编排和事务边界
- 领域服务封装跨聚合的业务规则
- 聚合根内的业务逻辑由聚合根自身保证
- 不变式由聚合根 + 领域服务共同守护
